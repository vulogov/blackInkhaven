# Road to 2.0 — Performance & Stability Verification

2.0 is gated on this document passing. 2.0 itself is the **semantic-net / knowledge-graph
flagship** (RFC forthcoming); the 1.x runway converges the feature surface, fixes
performance, and hardens — and *this* is the harness + checklist that proves it.

The measurement harness is built first so every subsequent change is measured, not
guessed.

## The measurement harness

Benches are **subprocess-based** (inkhaven is a bin crate; a lib+bin split — the enabler
for in-process render microbenching — is a tracked future refactor). They run the release
binary against a generated fixture.

### Fixtures

`inkhaven gen-fixture <path>` builds a deterministic project. Knobs:

```
inkhaven gen-fixture /tmp/fix \
  --books 5 --chapters 20 --paragraphs 100 \   # 10 000 ¶ (default)
  --target-words 450 --seed 0xC0FFEEDEADBEEF \
  --languages en,ru,fr,de,es \                 # multilingual (round-robin per book)
  --force
```

- **Scale:** `--books 25` → 50 000 ¶; shrink for quick runs. Same seed + shape → byte-identical.
- **Multilingual (2.0 harness):** `--languages en,ru,fr,de,es` spreads Cyrillic / accented /
  umlaut / ñ prose across the corpus, exercising tokenisation → embedding → search →
  export end to end. (Book titles carry a `[lang]` tag.)

### Running the benches

```
cargo build --release
./target/release/inkhaven gen-fixture /tmp/inkhaven-bench --force
INKHAVEN_BENCH_FIXTURE=/tmp/inkhaven-bench cargo bench
```

Current benches: `startup` (cold/warm list), `search` (3 query classes). **To add** for the
2.0 gate: `export` round-trip, `world compile`, an index-build/embedding-throughput bench,
and a **scale sweep** (10k / 50k fixtures).

### Idle CPU & frame render

These are TUI-internal and *not* subprocess-benchable. Until the lib split lands, measure
**idle CPU** empirically: launch the editor on a large fixture, leave it untouched 60 s,
sample CPU (`top`/`ps`). The current main loop repaints every ~200 ms even when idle
(≈5 fps) — the **event-driven-redraw** fix (repaint only on a dirty flag) is the headline
1.x perf change and this is how its win is verified (target: ≈0% idle CPU).

## Performance targets (proposed baselines to commit)

| Metric | Target | Where |
|---|---|---|
| Warm startup → first frame | < 300 ms | `startup` bench |
| **Idle CPU** | ≈ 0% | manual sample (post redraw fix) |
| Frame render p50 / p99 | < 8 / 16 ms (large book) | `render` bench (after lib split) |
| Search p50 / p99 @ 10k ¶ | < 50 / 200 ms | `search` bench |
| Save + reembed / ¶ | < 100 ms | `save` bench |
| Embedding / index build | linear in ¶ | new bench |
| RSS @ 10k / 50k ¶ | sub-linear, documented | `/usr/bin/time -l` |
| Regression gate | no > 10% vs baseline | bench compare (`_bench-report`) |

## Stability checklist (the 1.2.15 bar, re-asserted for 2.0)

Run the audits as a **multi-agent workflow** (the proven 4–6-agent pattern), each finding
adversarially verified before it counts.

- [ ] **No reachable panics** — audit `unwrap`/`expect`/`panic!`/slice-index/`as`-truncation
      in non-test paths (Critical/High gate).
- [ ] **Every persistent write is atomic** (`io_atomic`); no swallowed persist `Result`s;
      poison recovery on every lock; no silent data loss.
- [ ] **Fuzz / property** — malformed `world.hjson` / config / `.scriv` / imports;
      decompression-bomb caps (DEM already capped; extend to images / EPUB / imports).
- [ ] **Multilingual round-trips** — en/ru/fr/de/es Unicode through *every* export/import
      path (md / RTF / Scrivener / EPUB / PDF / CoNLL-U), lossless. Use a multilingual fixture.
- [ ] **Concurrency & soak** — bg vector-sync lock, vector threads, DuckDB single-writer
      under editor↔worldbuilder; hours-long soak watching RSS (leaks) + store (corruption).
- [ ] **Crash / restore** — panic-restore hook coverage; `kill -9` mid-write → store opens
      consistent (WAL / atomic); backup → restore byte-integrity.
- [ ] **Data integrity** — store → export → reimport round-trips; embedding index provably
      rebuildable; no orphaned nodes after delete/move.

## The 2.0 gate

Cut 2.0 only when: perf targets met (baselines committed, no regressions) · zero
Critical/High panics · every write atomic · all multilingual round-trips lossless · soak
clean · docs true. This checklist, filled in, is the gate.

## Known platform note

The Windows CI target (`x86_64-pc-windows-gnu`, MSYS2) currently fails at `ort-sys`
(ONNX Runtime via `fastembed`) — ort ships no gnu prebuilt. See the release workflow and
the tracking note; resolving Windows is independent of this gate (Linux/macOS are the
supported targets).
