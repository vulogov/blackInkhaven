# Inkhaven 3.0.0 — Stabilization & Feature Freeze Plan

**Status:** planning (2026-08-05, on `2.7.0-dev`). Chosen approach: **audit-first, then decide consolidation depth.**
**Supersedes:** the 2.7.0 BONDS direction — shelved. A feature freeze is the wrong moment to add a new analytical axis.

## Thesis — why this release is different

3.0.0 is not a feature. It is the promotion of the accreted 2.x surface to a **stable, maintained milestone**, after which work is restricted to bugs and changes to *existing* features. The economics invert:

> Today, surface debt is cheap — a chord remap, a CLI rename, a dead-module deletion cost nothing. **After the freeze, surface churn is expensive or forbidden** (it breaks the one user's muscle memory and contradicts the stability a major bump promises).

Therefore the pre-cut priority is **not polish** — it is doing everything that is *harder or impossible after the freeze* first. Bug-fixing is the post-freeze job; it must not be front-loaded. Surface-shape, schema, and coherence decisions are the opposite: this is the last cheap window.

## The surface being frozen (grounded 2026-08-05)

Last full-source audit was **pre-1.9** (`hardening-audit-1.9`, `premajor-audit`). The **entire 2.x arc** — SEMNET → GRAPHMIND → CHORUS → SENTINEL → LECTOR → REDLINE → CHRONICLE → KEN — has never been audited as a whole.

## Phases

### 3.0-P0 · Ambition — DECIDED: audit-first
Run P1 before committing to consolidation depth. The audit's findings (bug density, dead-code reality, schema state, coherence gaps) determine whether P2 is a full consolidation milestone or a minimal stabilize-and-freeze.

### 3.0-P1 · Correctness & stability audit — *the #1 freeze-blocker, and the next action*
A multi-agent adversarial full-source sweep (the `premajor-audit` pattern), partitioned so no agent's context overflows. Dimensions:

1. **Panic-surface triage.** Classify the ~2,350 `unwrap/expect/panic/unreachable` sites into *reachable* (I/O, parsing, indexing, arithmetic overflow, user/untrusted input) vs. *provably-safe* (post-check, static regex, owned-mutex-with-poison-recovery). Fix the reachable ones; leave the safe ones. Output: a ranked defect ledger, not 2,350 line edits.
2. **DoS / resource exhaustion** at book scale — unbounded loops, whole-file reads, quadratic passes, large-input parsers (revisit `premajor-audit` items: `calc.factorial`, non-ASCII import RTF/md/PDF).
3. **Silent data-loss** — atomic `io_atomic` writes everywhere prose/config/store is written; snapshot + backup integrity; store crash-safe write *ordering* (blob-before-meta); poison recovery.
4. **Schema durability** — confirm all ~26 DuckDB stores carry the `_inkhaven_schema` version anchor and migrate cleanly forward; no schema is frozen without a version.

**Deliverable:** a single findings ledger, most-severe-first, each item {file:line, class, failure scenario, fix}. This ledger is the input to the P0 consolidation decision and to the P2/bug backlog.

### 3.0-P2 · Surface consolidation — *the last cheap window (scope set by P1)*
Only as deep as P1 justifies. Candidate work, each item independently go/no-go:
- **Chord rationalization** — the map is saturated; if it needs remapping for learnability, now or never.
- **CLI verb coherence** — consistent naming/nesting across ~40+ subcommands.
- **Config completeness** — every block in `CONFIGURATION.md`; defaults preserve behavior; no orphan knobs.
- **Bund surface** — `every_registered_word_is_classified` green across all 35 stdlib modules; namespace consistency.
- **Dead-code prune** — the 147 `allow(dead_code)`: finish or delete.
- **Honest feature-cut pass** — with ~1 user, does every intelligence earn a permanent maintenance seat? Retire what doesn't *before* committing to it forever.

### 3.0-P3 · Documentation as the freeze contract
- Every feature: doc + tutorial + `KEYBINDING` + `CONFIGURATION` coverage (audit gaps vs. 116 tutorials).
- The 10 companion books re-audited to final scope; PDFs regenerated (the `1.6.6 books` ritual).
- A canonical **3.0.0 feature index** — the definitive map of the frozen product; becomes the maintenance reference.
- README + top-level positioning refreshed for the milestone.

### 3.0-P4 · Test & performance confidence
- Coverage sanity on the 2.x features; extend the never-panic proptest sweep to parsers added since 1.9.
- **Book-scale sweep (≈1000pp):** deterministic suite stays ≈$0, LLM features stay cost-capped, no per-frame FS / O(n²) survives (verify `premajor-audit` items cleared).

### 3.0-P5 · The 3.0.0 cut
Standard ritual (bump, `cargo update`, `cargo package` <10MiB, `cargo publish --no-verify`, GPG-signed `v3.0.0` tag under Vladimir Ulogov with **no attribution**, README, book PDFs, merge `--no-ff` via temp-file message, open the maintenance branch). RELEASE_NOTES framed as the **maturity milestone**; a MIGRATION note **iff** P2 introduced any breaking change.

## Sequencing
P1 (know the surface + its bugs) → P0 decision (consolidation depth) → P2 (consolidate using audit findings) → P3 (docs describe the *consolidated* surface) → P4 → P5.
