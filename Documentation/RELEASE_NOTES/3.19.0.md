# Inkhaven 3.19.0 — Every Key Answers

_3.19.0 is a verification release for the **TUI**. Seven passes, each a
headless probe that drives one surface of the running editor with every key
at nine terminal sizes and then a fix pass over what it found: the editor
widget, the text inputs, the modals, the tree pane, the right panes, the
chord layers and the overlays. Forty-odd defects — wrong-row clicks, dead
Esc arms, panics on small terminals, chords that could never fire — are
fixed; the probes stay in the tree as ignored tests so the next regression
is one command away. No new dependency, no new store; warning-free in
everything touched. Suite 3260 (+16 ignored)._

Full guides: [`KEYBINDING.md`](../KEYBINDING.md) (§4.5 the shared text-input
chord set is new; thirty rows updated) · [`CONFIGURATION.md`](../CONFIGURATION.md)
(`editor.tab_width`).

---

## The editor widget

**Clicks land where the mouse is.** With soft-wrap on, a click on a wrapped
line went to the wrong row and column: the renderer stored its scroll in
visual rows while the click handler read it as a source row. A pure
`click_to_source` now rebuilds the renderer's visual rows and maps the cell;
wide glyphs and unwrapped mode are unchanged.

**Keys that were documented but dead.** Smart `Home` was unreachable (plain
`Home` was consumed earlier; it works, `Shift+Home` extends). `PageUp` /
`PageDown` move by a viewport as the reference says, not by blank-line
paragraph. `Esc` with an `Alt+arrow` block selection cancels the selection
instead of changing focus. `Ctrl+D` on an empty line no longer eats the first
character of the next line.

**Non-ASCII replace.** Find/replace mixed byte and char columns: on accented
text the replacement clamped to the line end, deleted into the next line, or
landed in the wrong place. Both sides use char columns now.

**Tab width and undo depth.** `Tab` inserts up to the next multiple of
`editor.tab_width` (it inserted four spaces regardless) and `Enter` inside a
bracket pair indents by it; the undo history is 1 000 edits (it was
tui-textarea's 50 — under a sentence of typing). Every editor buffer —
external reload, snapshot accept, AI diff accept, replace-all — is built the
same way.

**Read-only buffers stay read-only.** `F3` file load, `F6` snapshot load and
the `ink.editor.*` words no longer write into a Help buffer; `Ctrl+G`
(previous match) is no longer refused as a mutation.

## One chord set for every text input

Some forty one-line fields each wired their keys by hand and had drifted.
They all go through one table now (`KEYBINDING.md` §4.5): printable insert
(Ctrl/Alt letters never insert — four filters used to type them), `←`/`→`,
`Home`/`End` and `Ctrl+A`/`Ctrl+E`, `Ctrl+←`/`→` and `Alt+B`/`F` word moves,
`Ctrl+U`/`Ctrl+K` kills, `Ctrl+W` / `Alt+Backspace` kill-word. The search
bar, AI prompt, shell pane, F1 help query, go-to-line, find/replace, rename,
add, facts search, concordance, every picker filter, the tree `/` filter and
the Output `/` query share it, and every one renders its cursor — a long
query windows to its box instead of hiding the cursor past the edge.

**One history recall.** The search, AI prompt, shell and help rings keep the
text you were typing as a draft and bring it back when `↓` passes the newest
entry (it was wiped); a sent prompt ends the walk so the next `↑` starts at
the newest.

**Multi-line boxes share the editor's chords.** The HJSON config editor, the
comment editor and the footnote editor use the paragraph editor's bindings
(cut/copy/paste through the system clipboard, `PgUp`/`PgDn`, `Ctrl+D` line
delete). All three protect unsaved text: the first `Esc` warns, a second
discards — the HJSON editor used to drop edits on one `Esc`.

## Modals

**No panic on a small terminal.** Every modal rect is fitted to the frame
and the eighteen clamps that asserted on a narrow frame are gone; below
32×8 the dispatcher paints a one-line notice instead of a panel. The probe
renders every reachable modal from 8×3 to 200×60.

**Esc reaches its owner.** Seven modals own `Esc` (the HJSON, comment and
footnote editors, the shell pane, the plan outline, world proposals, canon
commit); the dispatcher's generic close used to swallow the key before them,
so their staged discards, overlay-only closes and "back" steps were dead. The
F6 snapshot picker and the voice picker leave their `/` filter on the first
`Esc` and close on the second, like the other filter pickers. The voice
picker gains a real `/` filter mode, so a filter may start with `d`.

**Chorded confirmations are ignored.** `Ctrl+Enter` no longer confirms a
delete; `Ctrl`/`Alt` letters no longer fire the status filter, the
translation picker, the AI pane's apply keys or the Thoughts pane's clear.

**Lists window around the cursor.** Kill ring, style transfer, comments
panel, voice picker and the plan scene board no longer let the cursor walk
off-screen. An AI thesaurus result no longer replaces whatever modal is open.

## The tree pane

**Clicks map through the drawn rows.** Rows wrap, and the renderer never
wrote its scroll offset back, so a click on a scrolled or wrapped tree
selected the wrong row. The frame now records which row sits on each line
and clicks look it up.

**`o` cycles the cursor row.** It cycled the status of the paragraph open in
the editor whenever one was loaded. The `/` filter is a real text box and
leaving the pane keeps the needle as if `Enter` had been pressed.

## The right panes

**No dead ends.** `Home` in the AI response, `G` in Thoughts and a long
`PgUp` in the fullscreen chat set offsets past the content, so the opposite
key did nothing until the other extreme. Every scroll offset clamps to the
extent the last frame rendered.

**Search results and prompts.** The results overlay is clipped to the frame
(its 40-column floor panicked on a narrower terminal); the prompt picker
scrolls the selected candidate into view (a long list clipped at the box
bottom with the cursor off screen).

## The chord layers

**`Ctrl+B U` and `Ctrl+B J` work from the tree.** Two legacy tree-scoped
reorder aliases on the same chords won resolution, so undo-last-delete and
the Inner Socrates overview were unreachable from the Tree pane. The aliases
are gone; the bare tree keys `u` / `j` and `Ctrl+B ↑` / `↓` still reorder.

**The reference is complete.** A probe walks all 175 default bindings in
every pane they scope to — resolution, a before/after fingerprint of the
running app (no silent chord), two sizes, `Esc` — and checks `KEYBINDING.md`
both ways. Twenty bound chords had no row (F12, the shell chords, backup,
undo-delete, the status filters, five `Ctrl+V` chords); they have one now.

## The probes

Five ignored tests under `src/tui/app/` open a real project in a temp dir
and drive the `App` headlessly: `modal_probe` (118 openers, 1 left to an
installed WordNet), `tree_pane_probe`, `right_pane_probe`, `chord_probe`
and `overlay_probe`; the editor widget and the text-input table are covered
by ordinary unit tests. Run one with:

```text
cargo test --bin inkhaven -- --ignored --nocapture modal_probe
```

Each writes its report to `<temp dir>/inkhaven-<name>-probe.txt`.

## Upgrade notes

**`Ctrl+B U` / `Ctrl+B J` in the Tree pane** are undo-last-delete and the
Inner Socrates overview, as everywhere else. Reorder with the bare `u` / `j`
or `Ctrl+B ↑` / `↓`.

**Tree `o`** cycles the status of the cursor row, not the open paragraph.

**`Esc` in the HJSON, comment and footnote editors** warns first when the
box holds text; press it twice to discard.

**`Tab` in the editor** honours `editor.tab_width` (default 2); set it to 4
to keep the old width.

**Ctrl/Alt letters** no longer type into filters or fire single-letter pane
actions; a chord that no binding claims is ignored.
