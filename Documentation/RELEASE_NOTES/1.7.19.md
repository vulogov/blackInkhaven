# Inkhaven 1.7.19 — The Corpus Engine

_The Annotation Workbench gathered a language's texts; now you can query them. This
release opens Track B: a corpus engine over the stored interlinears. It answers the
two questions a corpus tool exists for — how *often* each word occurs, and *where* and
in what context — and reports the descriptive statistics only real usage can give. No
new runtime crates._

## Frequency and statistics

`frequency` reads the stored texts as a corpus and reports a word-frequency list plus
the numbers a dictionary can't: word tokens, distinct types, their ratio, and how
closely the frequencies follow Zipf's law.

```sh
inkhaven language frequency Eldar
```

```
corpus · Eldar
  texts 2 · tokens 7 · types 4 · lemmas 4 · TTR 0.57
  Zipf slope -0.87 (R² 0.93)

  frequency (by surface, top 20):
       3  kata
       2  mira
       ...
```

Add `--lemma` to count a root's inflected forms together (each token carries its
lemma from the gloss). This finally lights up the corpus-based metrics — type–token
ratio, the word-frequency Zipf fit — that the phoneme-level `metrics` verb couldn't.

## Concordance

`concordance --word W` shows every occurrence of a word across the stored texts, each
lined up with its context — a KWIC (keyword-in-context) view:

```sh
inkhaven language concordance Eldar --word kata --window 2
```

```
  kata mira  [kata]  nilo
       mira  [kata]  sana
```

`--lemma` matches a root's inflected forms too, so one search finds every form of a
word in use. Both are in the Linguistic companion, as `/frequency` and `/kwic <word>`.

## Dependencies & compatibility

**No new runtime crates.** Additive — a new `conlang::corpus` module over the stored
interlinears, two `language` verbs (`frequency`, `concordance`) and two companion
commands; `metrics::zipf_fit` is now shared with it. Nothing existing changes.
Warning-free (binary and tests). Test suite → 2575.
