# Inkhaven 1.6.8 — Verified Code

_Technical documentation's enemy is staleness — the example that was true two
releases ago. This release gives the docs author the fiction author's weapon: run
the example, flag it when it breaks. Plus free-text search in the Output pane and a
quiet unification under the inner readers. No new runtime crates._

## Verified code blocks (TDOC-1)

A code listing in your manuscript can now be checked the way the fiction track
checks a claim against the world: by **running it**.

- Mark a `para:code` listing's fence with `verify` — `` ```rust verify `` — and name
  a runner for its language in config. Inkhaven writes the snippet to a temp file,
  runs the configured command against it, and — if it exits non-zero — flags it in
  the **Output pane** on the exact paragraph, with the runner's output. A stale
  example becomes a red mark you can see.
- **`Ctrl+B Shift+D`** verifies the open listing; **`inkhaven docs verify`** checks
  the whole book (exits non-zero when any block fails, so it fits a CI step;
  `--dry-run` previews the commands, `--yes` confirms execution).
- Deterministic, zero AI, zero network — the only code that runs is what your own
  config declares.

```hjson
docs: {
  verify: {
    enabled: true
    runners: {
      rust:   "rustc --edition 2021 --crate-type lib {file} -o /dev/null"
      python: "python -m py_compile {file}"
      bash:   "bash -n {file}"
    }
  }
}
```

**Opt-in twice, by design.** Nothing runs unless you enable it *and* name a runner,
and only blocks marked `verify` are executed — illustrative or pseudo-code stays
untouched. A freshly-cloned project cannot run its examples without your explicit
`--yes`. Verification is never wired into the automatic/background/build paths.

The *Developing a story with Inkhaven* technical chapter gains a "Keep the examples
true" section covering it.

## Free-text search in the Output pane (PANE-2)

The Output pane — where every reader reports (fact-check, Socratic, Inner Editor,
translation, and now code-verification) — gains a **text filter**. Press `/` to open
a live query line and narrow the pane by substring (over the message text and kind),
composing with the existing source / severity / this-paragraph filters. `Enter`
keeps the query, `Esc` clears it. (Full-screen the pane with `Ctrl+Z f`.)

## The inner family, unified (INNER-GROUND-2)

An internal cleanup with no behavioural change: the intent ledger — the shared
"declared deliberate choices" surface that Inner Socrates, the Inner Editor, and the
Terms overlay all consult — moves into one neutral `crate::intent` module with a
single suppression predicate (`consult_raw`), removing the last copy of that logic.
The Inner Theologian's Bund words gain the consistent `ink.inner_theologian.*`
spelling (matching the other two readers), as real policy-gated words.

## Dependencies & compatibility

**No new runtime crates.** New config `docs.verify` (off by default); new command
`inkhaven docs verify` + the `Ctrl+B Shift+D` chord; the Output-pane `/` search.
Everything is additive — existing projects are unaffected. Test suite → 2332.
