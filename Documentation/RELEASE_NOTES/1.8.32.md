# Inkhaven 1.8.32 — Documentation Truth & TUI Hardening

_A correctness pass over the research companion book — every place the prose or a
screen diverged from what the code actually does — plus two pre-1.9 hardening wins that
make the editor's mandatory redraw cheap and keep routine saves from freezing the render
thread._

## The research book now matches the implementation

The RESRCH-6 chapter had been teaching the *reverse* of the design principle — that an
`--agentic` run produces a document — when it in fact **emits Facts into the Facts book**
and `--out` is only an optional run log. That framing is corrected, and a four-agent
audit of the whole of *Grounding Your Book in Fact* against the source fixed every
remaining divergence, including:

- **ch03** — the confirmation gate showed keys that don't exist (`e edit`, `c check`);
  the real gate is `Tab` between the title/body fields, type to edit, `Ctrl+S` keep, `Esc`
  discard, with the fact-check running automatically on confirm.
- **ch02** — the "command palette" that "opens" is really a one-line hint bar plus
  `Tab`-completion (full list under `Ctrl+B h`); the status-bar screen now shows the real
  segments (`[RAG: …] · [$…] · [?:help q:quit]`).
- **ch10** — `/calc` reads *postfix* words (`100 mi2km`, not `100 mi to km`); the World
  layers are Astronomy / Geology / Climate / Hydrology / Demographics.
- **ch07** — `/triangulate` queries Wikidata + OpenAlex + arXiv in one pass (not GeoNames,
  not "concurrently").
- **ch05 / ch06** — `/gutenberg <PG#>` and `--chapter N`; `/web --chat` and the
  `research.web.pipeline` default.
- **Appendix A** — `/diff` takes no argument and is tuned by `diff_top_n`; added `/review`,
  `--agentic`, and `--snowball`; fixed `/triangulate`. **Appendix B / glossary** — `promoted`
  is gate-skipped, the fact-check gate also fires for imported documents, and some origins
  carry no tier glyph.

New faithful `screen()` frames were added where a chapter described interactive output but
showed none: the Wikidata and GeoNames cards, `/triangulate`, the `/factcheck` verdict
tree, `/calc` + `/world`, and `/undisputed`.

**Code fix surfaced by the audit:** `/review` (new in 1.8.31) was wired into the parser and
dispatcher but never registered in the command `SPECS` table, so it did not tab-complete or
appear in the query-prompt hint bar. Registered. The RESRCH-6 CLI progress/warning glyphs
(`⟳`, `⚠`) — which neither the book's monospace font nor some terminals render — are now `»`
and `!`, and the agentic completion message points at `/review`.

## Pre-1.9 hardening

Two items from the pre-1.9 stability/performance audit, both making the editor's
unconditional per-frame redraw affordable rather than switching to event-driven repaint:

- **Editor syntax-highlight cache.** The editor repaints every frame (~5×/sec even when
  idle) and each repaint re-ran the whole-buffer tree-sitter / lexer highlight — the single
  largest per-frame cost. It is now memoized in `OpenedDoc`, keyed by a content hash of the
  buffer plus the content type. An idle frame reuses it; any edit changes the hash;
  switching paragraphs resets it. (The highlight is per source line and the theme is fixed
  for a session, so neither participates in the key.)
- **Vector index flushed off the render thread.** A paragraph save called the vector
  `sync()` on the UI thread, holding the store mutex while serializing the entire HNSW index
  to disk — a hitch on every save of a large corpus. The routine save path now flushes on a
  detached thread. This is durability-safe: the paragraph content is already persisted (the
  metadata/blob write fsyncs per commit), and `vecstore`'s save writes atomically (temp file
  + rename), so a crash mid-flush keeps the last good index and the pending embedding is
  recomputed on next access — no user data is at risk. The periodic background tick and the
  quit-path sync stay synchronous, so the on-disk index always converges.
