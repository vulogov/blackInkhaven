# Inkhaven 3.13.0 — Tend the Ledger

_3.12.0 made the Canon Ledger's dependency graph populate itself. 3.13.0 is the
maintenance trio that keeps it healthy now that the graph holds real edges:
backfill an old ledger, reclaim the append-only churn, and see the whole shape.
Deterministic core, warning-free, no new dependencies._

Full guide: [`CANON.md`](../CANON.md).

---

## `canon reground` — backfill an existing ledger

Grounds are inferred at creation (3.12), but a ledger recorded *before* 3.12 — or
one whose decisions entered ungrounded — has an empty graph, so `canon impact` /
`why` come back empty on it. **`inkhaven canon reground`** runs the same
deterministic inference (kind rules + shared content words, in your project
language) across the *whole* live ledger and draws the missing edges, no re-harvest
needed. **`--dry-run`** previews the edges it would add without writing; the pass is
idempotent, so a second run is a no-op.

## `canon compact` — reclaim the churn, safely

Grounding a decision mints a new version that *supersedes* the old one, so a ledger
that's been hand-tended accumulates superseded versions. **`inkhaven canon
compact`** drops the ones nothing live needs (via smysl's `compact`). It's pure
bookkeeping — live decisions keep their ids and their grounds — with one guarantee
worth stating: a regrounded decision's **commitment is preserved**. (A commitment
lives on the version it was made against; compacting away a superseded predecessor
would otherwise lose it, so `compact` carries the commitment onto the live version
first, then drops the old one.)

## `canon graph` — see the whole shape

**`inkhaven canon graph`** renders the grounds DAG as an indented walk: each
**foundation** (a decision that rests on nothing) followed by what transitively
rests on it, so the load-bearing choices and their blast radius read top-down.
`canon graph <id>` shows just one decision's subtree.

## Scripting

`ink.canon.graph` `( -- list )` joins the read-only Bund surface — the grounds
adjacency (`{uid, kind, gist, commitment, grounds}` per decision). The writes
(`reground`, `compact`, `commit`, `ground`/`unground`, harvest) stay CLI/TUI.

## Also in this release

A pre-publish fix folded into 3.12.0 is carried here too: **`canon check` follows
regrounding** — it had iterated raw versions and read commitment directly, so after
a `canon ground` a canonical-resting-on-floated situation could slip the check;
it now skips superseded versions and follows the supersession lineage.

---

## Upgrade notes

Nothing to migrate. If your ledger predates 3.12.0, run **`canon reground`** once to
populate its grounds (then `impact`/`why`/`graph` light up); run **`canon compact`**
whenever hand-grounding has left churn you'd like to reclaim. Both are optional and
deterministic.
