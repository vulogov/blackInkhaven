# Inkhaven 1.8.23 — Storage & write-safety hardening

_The first of two hardening cuts from the pre-1.9 audit. Finding writes are now atomic, no
longer silently swallowed, and a live-file write path that bypassed atomic-write is fixed —
plus two poetry-layer correctness fixes. **No new runtime crates.**_

## Atomic finding writes (no more half-state)

`StorageEngine` gained a `transaction()` wrapper (BEGIN → closure → COMMIT, or ROLLBACK on
error). The Inner Poet's `replace_findings` and the Inner Editor's engage-persist now run
their DELETE + N inserts (+ engagement stamp) inside one transaction — so a failure or crash
mid-write leaves the **prior** finding set intact rather than a partial or empty one, and a
concurrent reader never observes the gap. (Rollback is unit-tested.)

## Persist errors are surfaced, not swallowed

The Inner Editor engage worker and the Inner Poet fast track previously discarded the result
of writing findings to disk (`let _ = …`) — so the UI could show findings, refresh badges, and
spend a paid LLM call while **nothing reached disk**, only to vanish on restart. Now a persist
failure is logged (engage worker) or shown on the status bar (`findings shown but not saved —
…`), so silent data loss and wasted calls surface.

## Atomic writes on live files

- `ink.paragraph.save` (the scripting builtin) wrote the live `.typ` file with a non-atomic
  `std::fs::write` — it is the *only* writer of that file (`update_paragraph_content` writes the
  blob store, not the file), so a crash mid-write could truncate a paragraph. Now routed through
  `io_atomic::write`.
- The AI-lift "file this generator output into the book" path (`Ctrl+…` → `L`) had the same
  non-atomic write for its draft files — also fixed.

## Poetry correctness

- **Per-stanza forms no longer collide.** `poem_form_for` was "first sibling in the group wins",
  so stanza 2 resolved to stanza 1's form and re-declaring a form on stanza 2 rewrote stanza 1's
  sidecar. It now finds the sidecar that belongs to *this* stanza (the block immediately following
  it), with the group-level cascade as fallback. The Outline detail panel also stopped recomputing
  the same poem status 2–3× per frame.
- **Over-length forms no longer show "complete ✓".** A 16-line "sonnet" showed `16/14 ✓` (green)
  while the checker flagged it as too long; a bounded form is now complete only at its exact count.

## Also

The shared `inner_poet.db` handle is now held once on the app instead of reopened on every
ambient scan (killing per-navigation `Connection::open` churn). The broader shared-handle
refactor for `inner_editor` / `inner_socrates` (the transient file-lock display glitch during
an engage) lands with the TUI-performance cut in **1.8.24**.

## Dependencies & compatibility

**No new runtime crates.** Additive `StorageEngine::transaction`; behaviour changes are
strictly safer. Warning-free (binary and tests). Test suite → 2660.
