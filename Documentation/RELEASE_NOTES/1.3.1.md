# Inkhaven 1.3.1 — Submission track

_On top of 1.3.0 (Print production / PDF-1).  1.3.0 shipped the **print**
track of pillar A — "From Draft to Submission".  1.3.1 ships the
**submission** track: getting a finished manuscript in front of an agent
or editor.  Pure-Rust, no external apps, no new runtime dependencies.
Full design: [SUBMISSION-1_PLAN.md](../PROPOSALS/SUBMISSION-1_PLAN.md);
walkthrough: [Tutorial 66](../Tutorials/66-submission-package.md)._

## The Word document agents require

The Shunn manuscript *format* already shipped (`inkhaven manuscript`,
1.2.19) — as typst. But most agents require **Word**. `inkhaven docx`
emits a Shunn-format `.docx`:

```sh
inkhaven docx --book-name "My Novel" --author "Jane Writer" \
    --contact "Jane Writer\n12 Wharf Rd\njane@example.com" --font times
```

Title page (contact corner + rounded word count + centred title/byline),
double-spaced 12 pt Times/Courier, 1″ margins, ½″ first-line indent, a
`Surname / KEYWORD / page` running header from page 2, scene breaks as a
centred `#`, each chapter on a fresh page — reusing the same model as
`manuscript`. **Hand-rolled OOXML** over the in-tree `zip` (the audit
rejected `docx-rs`: it hard-pulls a second major version of `zip` — the
same duplicate-dependency tech debt the lopdf `embed_image` audit
rejected). `docx` is also a `Ctrl+B O` book-take.

## The submission package (AI)

A novel doesn't fit a prompt, so the generators work against a compact
**digest** — title / author / length / a one-line summary of each chapter
+ your Characters and Threads books, cached in `.inkhaven/digest-<slug>.json`
and rebuilt only when the manuscript's structure changes:

```sh
inkhaven submission digest                    # build / refresh the context
inkhaven submission query                     # one-page query letter
inkhaven submission synopsis [--long]         # one-page / 2–3 page, full arc
inkhaven submission comps                     # comp-title suggestions
inkhaven submission logline                   # logline + elevator pitch
```

Each drafts into the new **Submissions** system book (overwriting the same
piece, not piling up) and prints it. Synopses spoil the ending by design;
comp titles are Local-pinned, general-knowledge **suggestions** — labelled
as such, never citing sales figures. From the editor, **`Ctrl+V q`** picks
a generator and streams it into the AI pane; its system prompt resolves
through the usual three tiers (a `submission-*` paragraph in the Prompts
book → `prompts.hjson` → built-in, language-aware), so the house voice is
tunable.

## The tracker

Where it went, when, and what came back — the `.inkhaven/submissions.json`
log, with a **`Ctrl+V u`** modal:

```sh
inkhaven submissions add --market "Dream Literary" --agent "A. Reader" --status sent
inkhaven submissions status S1 offer          # stamps a response date
inkhaven submissions add-note S1 "got a call — requested first 50 pages"
inkhaven submissions list [--json|--status sent|--open]
```

`add-note` is a **timestamped event trail**, so a record reads as a
history (sent → requested edits → round two). In the modal, `↑↓` move,
`Space`/`s` cycle status, `d` removes; the selected record expands to show
its trail. Link a generated draft with `--draft <slug>`.

## Scripting (Bund)

Five `ink.export.*` words — `docx | manuscript | markdown | tex | epub`,
each `( book path -- )` — so a release script emits every prose artefact in
one pass, alongside the `ink.pdf.*` print pipeline. All `fs_write`-gated
and path-sandboxed like every disk-crossing `ink.*` word.

## Notes

- **System book:** `Submissions` joins `SYSTEM_BOOKS` (after Language).
  Existing projects pick it up automatically on the next open via
  `ensure_system_books` — the same path that seeds any system book. (A
  binary older than 1.3.1 won't show it; update with `cargo install
  inkhaven --force`.)
- **Zero new dependencies.** The `.docx` writer is hand-rolled OOXML; the
  generators reuse the existing LLM stack; the tracker is `serde` + a
  JSON sidecar.
- Tests 1270 → 1286. One new tutorial (66).
