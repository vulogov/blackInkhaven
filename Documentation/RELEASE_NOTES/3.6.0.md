# Inkhaven 3.6.0 — Faithful Exports, a Trustworthy Worklist

_A **widen-and-polish** release: no new capability, entirely fixes and finish.
It makes the export/import paths keep everything you wrote, makes the reader
worklist honest, gets Spanish and French scansion right, and gives the reader
dashboards consistent navigation._

Four tracks, all from a five-agent source audit. Deterministic, no new runtime
crates, warning-free throughout; the suite grew to **2998**.

## Track A · Export / import fidelity — stop losing what you wrote

The headline was a silent data-loss bug: **authored emphasis and footnotes never
reached the submission exporters.** `collect_chapters` flattened every paragraph
through the text-to-speech cleaner (which strips `*`/`_` and drops
`#footnote[…]`) *before* the manuscript `.typ` and `.docx` builders ran — so the
3.4.0 emphasis work was dead in the real pipeline and every bold/italic/footnote
rendered plain. Seven fixes:

- **Emphasis survives** into `inkhaven manuscript` and `inkhaven docx` — a new
  manuscript-prose flattener preserves the `*`/`_` delimiters (the text-to-speech
  path is now correctly separate).
- **Footnotes survive** — the typst manuscript passes `#footnote[…]` through as a
  real typst footnote (its body prose-escaped), and the `.docx` gains a real
  `word/footnotes.xml` part: body markers become superscript
  `<w:footnoteReference>` runs with document-wide ids.
- **EPUB footnote ids are unique per chapter.** They used to restart at `fn-1`
  every paragraph, so a chapter with two footnotes emitted duplicate ids (invalid
  XHTML — every note-link jumped to the first note) and scattered footnote
  sections mid-chapter. Now a chapter is finalized in one pass: unique ids, one
  trailing section.
- **Imported inline images no longer eat the rest of the paragraph.** An
  imported `<img>` became a `//` line comment, which in typst runs to end-of-line
  — so any prose after the image on that line vanished at compile time. It is now
  a block comment.
- **Third-party EPUB blockquotes and tables are preserved.** A `<blockquote>`
  becomes `#quote[…]` (was flattened to a plain paragraph); a `<table>` becomes a
  real `#table(columns: N, …)` (its cells used to concatenate into one run-on
  paragraph). Export gained the reverse — `#quote[…]` → `<blockquote>` — so quotes
  round-trip.
- **The `.docx` title page stays literal.** A contact line like
  `jane_q_writer@example.com` was being emphasis-parsed, italicising `_q_` and
  eating the underscores; the title/byline/contact fields now emit plain runs
  (matching the typst path). Body prose still carries emphasis.
- **Markdown export stops mangling stray asterisks.** `multiply 3 * 4 * 5` used to
  become bold; the exporter now uses the same whitespace-adjacency guard the HTML
  exporter has, so arithmetic and literal `*` survive.

## Track B · The reader worklist, made trustworthy

Five correctness fixes to the unified Editorial Pass worklist (`Ctrl+V Shift+R`,
`inkhaven edit`):

- **Distinct occurrences no longer collapse.** Dedup compared only
  category + message + chapter, so two occurrences of the same word ("very") in
  one chapter merged into one — the second became unreachable, invisible even to
  the batch `F`. It now dedups by the full location (paragraph + span).
- **Praise stops sitting in the worklist.** The Inner Stylist's celebratory "every
  voice is distinct" observation leaked in as an Info on any healthy
  multi-character book, so "✓ reads clean" could never fire. Praise is now dropped
  (as it already was for the Inner Editor).
- **Book-level findings don't false-anchor.** A whole-book continuity or
  read-through finding (chapter 0) resolved onto chapter 1's first paragraph and
  offered a misleading ⏎ jump. Book-level findings now correctly have no anchor.
- **Voice-drift is disambiguated from semantic drift.** Both shared the `drift`
  category; the anchorless voice observation was routing to a dead-end Decision
  and sharing a filter bucket with the (anchored) world-drift finding. It's now
  its own `voice-drift` category (a Brief).
- **No category shows a fix affordance it can't honor.** A dead `voice` Rewrite
  category (no recipe, no producer) would have shown the ✎ glyph with a no-op
  `f`; it's removed, and the guard now asserts every Rewrite category has a recipe.

## Track D · Scansion that works in Spanish and French

Two poetry-engine fixes, each answering "does it work in that language?":

- **Spanish written accents drive stress.** The scanner recognized only the
  combining acute mark, so precomposed accented vowels (á/é/í/ó/ú) — Spanish's
  orthographic stress mark — were ignored, and common oxytones (`está`,
  `corazón`, `canción`, `café`) scanned on the wrong syllable, corrupting metre
  *and* rhyme. Now the written accent wins (gated to Spanish — in French those
  mark vowel quality, not stress).
- **French rhyme gender is correct.** French rhyme type was pinned to *masculine*
  for every word (a stress-count that's always zero for phrase-final French), so
  feminine rhymes — the mute-final-`e` endings like `pensée`/`table`/`chantent` —
  were unreachable. Rhyme gender is now read from the ending, as French prosody
  actually works.

## Track C+E · Ergonomics & symmetry

- **`Esc` in Thread-Weave returns to its picker** instead of closing everything.
- **`Esc` while typing a `/` filter** (Comments / Style-transfer / Threads
  pickers) now leaves filter-input mode and stays in the list; a second `Esc`
  closes — matching the snapshot browser.
- **The seven reader dashboards share richer navigation.** `↑/↓`, plus
  **PgUp/PgDn** (by a page), **Home/End**, all **skipping blank separator rows**
  so `Enter` always lands on a real row. (No vim `j/k` — those collide with the
  per-dashboard `k`/`m`/`l` chords.)
- **`inkhaven bonds --ledger`** — the declared-`rel:` model grouped by character
  pair, the exact mirror of `knowledge --ledger` (its Bund `ink.bonds.ties` read
  already existed; the CLI flag was missing).
- **`ink.world.findings`** — the discrete world conflicts + anachronisms as a
  list, matching `ink.knowledge.findings` / `ink.bonds.findings` (world could
  report the issue *count* but not enumerate them).
- **Dead graph surface removed.** Two `EdgeKind` variants (`Synonym`,
  `SimilarTo`) that nothing ever produced are gone.
- **The scripting policy guard is tightened** — it now polices every word
  inkhaven registers (computed as a diff), not just the `ink.`-prefixed ones, so a
  future bare word touching a protected resource can't slip the classification.

## Deferred as follow-ups

Authored `#table(…)` *export* to EPUB (rare in hand-written manuscripts; typst
still compiles it to PDF), and alias resolution (still gated on its architectural
decision).

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).
