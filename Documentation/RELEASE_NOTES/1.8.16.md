# Inkhaven 1.8.16 — Poetry CLI Polish (POEM PO-P10)

_Machine-readable output and a CI gate for the poetry commands. `--json` gives structured
findings and results; `--fail-on-concern` fails the run when a poem has drifted from its
declared form. **No new runtime crates.**_

## `--json` and `--fail-on-concern`

```sh
inkhaven poetry scan --form blank_verse --text "…" --json
inkhaven poetry scan --form sonnet --text "…" --fail-on-concern   # exit 1 on a Concern
inkhaven poetry status --form villanelle --text "…" --json
inkhaven poetry rhyme дом том --language ru --json
```

- **`--json`** on `scan`, `status`, and `rhyme` — structured output for tooling and CI: the
  scan reports its findings (severity / kind / line / message) plus a `concerns` count; the
  status reports the line ratio, completeness, and issues; the rhyme reports quality, type,
  shared tail, and note.
- **`--fail-on-concern`** on `scan` — exits non-zero when any Concern-level finding is
  present, so a CI job can catch a poem that has drifted from its declared metre or rhyme.

`--dry-run` is a no-op here — none of the `poetry` commands write to a store; they only
compute and report.

## Dependencies & compatibility

**No new runtime crates.** Adds `--json` to `poetry scan` / `status` / `rhyme` and
`--fail-on-concern` to `poetry scan`; no behaviour changes to the default text output.
Warning-free (binary and tests). Test suite → 2653.
