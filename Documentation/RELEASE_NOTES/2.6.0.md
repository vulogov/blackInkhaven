# Inkhaven 2.6.0 — KEN: Who Knows What, When

_Inkhaven watches where a character is, whether they exist yet, whether the world
holds together, how their arc bends, whose head we're in. None of it watches the one
thing a mystery lives or dies on: what a character **knows**._

The flagship of 2.6.0 is **KEN** — epistemic continuity. Its thesis:

> **KEN is SENTINEL's "referenced-before-introduced" invariant, extended to
> knowledge.** SENTINEL flags an entity named before it exists; KEN flags a character
> acting on a fact before they could know it — a leaked secret, a premature reference,
> a reveal that never lands.

It is **deterministic and free** at the core, **advisory** (it never edits prose), and
it produces a finding a generic AI structurally cannot: reconstructing who-knows-what
across a whole book needs the timeline, the event-participant lists, the character
bible, and scene POV that only inkhaven maintains. It adds **no new runtime crates**.

## The grant — when could they know it?

KEN never guesses. A character's *ken* is derived two deterministic ways:

- **Presence** — a character in a timeline event's participant list knows that event
  from the moment it happens (free, from the structure you keep).
- **Declared** — `secret:<topic>` marks a secret, `know:<topic>[@<name>]` grants a
  character, `reveals:<topic>` binds an event to the fact it reveals.

A *use* — a character referencing a topic in their attributed dialogue or their POV
scene — is caught by SENTINEL's Unicode-aware mention matcher over DIALOG-1's speaker
attribution. A reference before the earliest grant is the break.

## What it catches

- **`premature_knowledge`** — a character references a topic before their earliest
  grant ("Bob speaks of the murder in ch. 4 — before learning it in ch. 6").
- **`leaked_secret`** — a `secret:` topic referenced by someone never granted it.
- **`dropped_reveal`** — a declared reveal whose topic never surfaces again (the
  epistemic `unpaid_setup`).
- **`implied_irony`** *(opt-in `--deep`)* — a character acting informed/ignorant
  *without naming* the topic — the subtle case, on a cost-capped LLM pass.

## The surfaces

```
inkhaven knowledge          # the deterministic check (non-zero exit on a break — a CI gate)
inkhaven knowledge --json   # the findings as JSON
inkhaven knowledge --deep   # + the opt-in, cost-capped implied_irony pass
```

- **`Ctrl+B Shift+Z`** opens the knowledge dashboard (findings grouped by kind, Enter
  jumps to the paragraph) — the last free `Ctrl+B` chord.
- Knowledge findings ride the **`Ctrl+V Shift+R`** Editorial Pass (a `knowledge`
  source, routed **Decision**: fix the leak, move the reveal, or add a grant) and
  `inkhaven revise`.
- `ink.knowledge.{grants, findings, check}` — read-only Bund (`check.clean` = no hard
  break; the `--deep` pass is not exposed).

## Cost — a design invariant

The core is a forward walk + set membership + mention matching — **no model, ≈ $0 at
any book size**, scaling with declared topics, not pages. It is **self-gating**: no
tags and no events → no work. The only LLM touchpoint is the opt-in `--deep` pass,
cost-capped on the world fact-checker's rail. There is deliberately no "judge what
everyone knows" whole-book pass.

## Multilingual & config

KEN inherits SENTINEL's Unicode mention matching and DIALOG-1's EN/RU/DE/FR/ES dialogue
conventions. There is **no new config block** — KEN reuses the existing `llm` and
`language`.

windows-gnu prebuilt).
