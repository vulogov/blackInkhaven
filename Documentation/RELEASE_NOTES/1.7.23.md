# Inkhaven 1.7.23 — Testing a Hypothesis

_The register recorded your diachronic claims; now it can test them. A sound-change
hypothesis can be run through the Consequence Tracer, turning "I think \*k became tʃ
before front vowels" from an assertion into a concrete prediction — these words shift,
these two collapse into homophones — that the lexicon either bears out or refutes. The
comparative method, closed into a loop. No new runtime crates._

## Checking a hypothesis

`hypothesis-check` runs the Consequence Tracer over a sound-change hypothesis's claim:

```sh
inkhaven language hypothesis-check Eldar --id front-k
```

```
? hypothesis-check · Eldar · `front-k` [proposed]
  claim: k > tʃ / _ i
  affects 3 of 40 analyzable word(s)
  changes:
      kina  >  tʃina  'star'
      keru  >  tʃeru  'river'
  ⚠ 1 new homophone set(s) (2 words merged):
      tʃina ← tʃina, tsina
```

Now the claim is falsifiable: if the predicted forms match what you expect, move it to
*supported*; if it merges distinctions you meant to keep, that is your evidence to
*refute* it. The check runs only on sound-change hypotheses — a cognacy or borrowing
claim isn't a rewrite rule — and is `/hcheck <id>` in the companion.

This closes the register's loop into the comparative method: propose a change, trace
its consequences, and record whether it held.

## Dependencies & compatibility

**No new runtime crates.** Additive — a `hypothesis-check` verb and a `/hcheck`
companion command, reusing the Consequence Tracer (`trace_sound_change`); the trace
report body is now shared between `trace` and the check. Nothing existing changes.
Warning-free (binary and tests). Test suite → 2581.
