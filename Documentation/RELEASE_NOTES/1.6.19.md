# Inkhaven 1.6.19 — Validated Loci

_A cited passage is only as good as the passage being real. This release completes
the primary-source apparatus from 1.6.18: `@key[locus]` citations are now checked
against a reference scheme, canonicalized so variant spellings collapse, and linted
live in the editor. No new runtime crates._

## Reference schemes — validate a locus

`@bible[John 3:sixteen]` compiles without complaint — Typst has no idea "sixteen" is
not a verse — and quietly ships a reference no reader can follow. Now a locus is
checked against a **reference scheme**, a grammar for what a well-formed reference to
that source looks like:

- **Built-in, zero-config** for the scripture keys — `bible` / `book-of-mormon`
  (`{book} {ch}:{v}`, Unicode book names, numbered books) and `quran`
  (`{surah}:{ayah}`). Ingest a chapter with `/bible` and its loci validate with
  nothing to configure.
- **User-defined** via `sources.ref_schemes` — a named `{ pattern, format }` (e.g.
  `kant-ab: { pattern: "^A\\d+(/B\\d+)?$", format: "A{n}/B{n}" }`), assigned to a
  source with a `scheme:` line in its Sources entry.

A malformed locus is **reported, never silently dropped**. `inkhaven index-locorum`
lists every malformed reference with its expected format; `--strict` turns that into a
non-zero exit fit for a continuous-integration step, and `inkhaven build` logs a
warning per malformed locus.

## Canonical loci — variant spellings collapse

The scheme does a second service: it **canonicalizes**. Write `@bible[Jn 3.16]` today
and `@bible[John 3:16]` tomorrow — or, in a Russian project, `@bible[Иоанна 3:16]` —
and the Index Locorum resolves all three to one entry, `John 3:16`, rather than three
near-duplicates under the same source. Bible references resolve the book name (full
names, prefixes, Russian→English, or a number) and normalize the chapter–verse
separator; the Qur'an and Book of Mormon normalize the separator; a source with a
custom scheme (or none) is left verbatim, so a tradition that legitimately uses dots
is never mangled.

## A live editor lint — `Ctrl+V c`

Catch a malformed locus as you write. `Ctrl+V c` lints the open paragraph's
`@key[locus]` citations against their sources' schemes and drops a **⚑ warning** into
the Output pane for each malformed one, anchored to the paragraph — the deterministic,
zero-AI, editor-side twin of `inkhaven index-locorum`'s check, beside the `Ctrl+V
Shift+C` sourcing pass. A source with no scheme leaves its loci unchecked.

## Documentation

The _Theology and Philosophy with Inkhaven_ companion manual gains a "Validate the
loci, and let them canonicalize" section in its citation chapter, so the worked
example now covers the whole loci story from `@key[locus]` to a validated, canonical
Index Locorum.

## Dependencies & compatibility

**No new runtime crates.** New config `sources.ref_schemes` + `BibEntry.scheme` (both
opt-in; the scripture keys carry built-in schemes); new editor chord `Ctrl+V c`; new
`--strict` flag on `inkhaven index-locorum`. Everything is additive — a source with no
scheme is unvalidated exactly as before. Test suite → 2448.
