# Inkhaven 1.8.8 — The Syllabifier (POEM-2, PO-P2)

_Natural-language syllabification for the five project languages — the layer every metre,
rhyme, and Inner-Poet feature depends on. And the RFC's one proposed dependency turned
out to be unnecessary: Typst's own hyphenation crate was already in the tree. **No new
runtime crates.**_

## Syllabifying real words

`inkhaven poetry syllabify` breaks a word (or a whole `--line`) into syllables and marks
the stressed one:

```sh
inkhaven poetry syllabify --line "У лукоморья дуб зелёный" --language ru
#   лукоморья    лу·ˈко·мор·ья  (4 syl)
inkhaven poetry syllabify extensive --language en
#   extensive    ex·ˈten·sive  (3 syl)
```

The library (`src/poetry/syllabify.rs`) provides `syllabify`, `syllable_count`,
`mora_count`, and a conlang bridge, over English, Russian, German, French, Spanish, plus
a vowel-count fallback for anything else.

## Reliable counts, not just breaks

Syllable **boundaries** come from Liang hyphenation, but Liang under-counts syllables (it
suppresses word-edge single-vowel breaks — "hello" yields *one* segment for a two-syllable
word). So the **count** is taken from vowel nuclei, which is reliable and ~exact for
Russian, and English **silent final-e** is handled so "extensive" is three syllables, not
four. Stress is a per-language rule layer (Russian penult/antepenult, English penultimate,
German initial, Spanish penult-or-final, French phrase-final) — a lexical stress dictionary
is a later refinement, and in verse the author's own stress marks override it.

## No new dependency — thanks to Typst

The RFC proposed adding the `hyphenation` crate (≈2.8 MB of pattern data). Verification
found two things: Liang undercounts (so we need vowel-counting regardless), and — Vladimir's
catch — **Typst already hyphenates internally via `hypher`**, which is therefore already in
our dependency tree. So we use `hypher` (promoted to a direct dependency, five languages
enabled) and add **no new crate to the build** — a better outcome than the RFC.

## Dependencies & compatibility

**No new runtime crates.** `hypher` was already present transitively via Typst; this
promotes it to a direct dependency with the five project languages. Purely additive — a new
syllabifier module and a `poetry syllabify` diagnostic command. Warning-free (binary and
tests). Test suite → 2625.
