# Inkhaven 3.3.0 — Wider Reach, Sharper Tools

_A **widen-and-polish** release: no new reader, no new axis. It takes capabilities
Inkhaven already has and makes them reach further — to more languages, into the
scripting layer, and through a smoother revision loop._

Three tracks, all expansions of existing features. Deterministic, no new runtime
crates.

## 1 · Multilingual parity

A per-reader audit found four features that silently narrowed outside English;
this closes the ones that a word-list or a lookup table can honestly fix:

- **SENTINEL numeric** — the direction-reversal / conflicting-duration detector
  covered EN/FR/ES only; **German and Russian** books produced zero findings.
  Added `german()` + `russian()` continuity lexicons — Russian with the
  **case-inflected unit forms the counting construction demands** (`день` / `дня`
  / `дней`, `год` / `года` / `лет`) and the `верста` unit; German with dative-
  plural forms (`Tagen`). A new per-language `direction_preps` set catches a
  prepositional direction (`nach Norden`, `на север`).
- **CHORUS register** — German and Spanish prose were being matched against the
  *English* contraction/archaism/formality word lists (near-zero hits → a false
  "clean register"). Added curated **DE + ES** lists.
- **Inner Socrates tense-shift** — ran for English only; now runs for **DE/FR/ES**
  via per-language auxiliary tables, and renders its question in that language.

Honest limits kept as limits: Inner Socrates **pronoun-ambiguity** stays English-
only (coreference needs a parser, not a word list), and CHORUS's **Russian tense
slip** stays surfaced-as-unsupported (Russian tense is aspect-driven — the tense-
shift reader excludes it for the same reason). CHORUS POV/head-hop needed
nothing — the audit confirmed it already works in all five.

## 2 · `ink.world.*` Bund

The last parked scripting namespace. MYTH, coherence, continuity, and the world
timeline were already wrapped; the gap was the core `inkhaven world` report. Three
read-only words, reusing the existing report path (no new read logic):

```
ink.world.report      ( -- dict )  entity inventory + issue counts + summary
ink.world.undescribed ( -- list )  {name, kind} defined but never named in prose
ink.world.check       ( -- dict )  {issues, undescribed, clean} — a pre-submit gate
```

Classified `store_read`, documented in `WORD_REFERENCE.md`, guarded by the
usual classification + doc-match tests.

## 3 · Editorial Pass ergonomics

Two frictions in the revision loop, fixed:

- **Session skips now persist.** `s` ("skip this session") only hid a finding
  from the *open* modal — reopening the pass brought it right back. It's now a
  real session-scoped skip that survives closing and reopening the pass (clears on
  restart); `D` clears deferrals *and* session skips.
- **Filter by response kind.** Beside the `[`/`]` category filter, **`r`** now
  cycles a response-kind filter (✎ Rewrite / ⇄ Decision / ✉ Brief). The two AND
  together, so you can narrow to *just the decisions you owe* or *just the
  batchable rewrites*; `F` fix-all stays consistent with the view.

## Roadmap note

**Alias resolution** (nicknames / epithets resolving to a character across every
reader) was considered and **postponed** — not dropped. It touches the shared
mention-matcher five readers depend on and is gated behind an architectural
decision (global vs. reading-order-scoped resolution); it earns its own release
with a proper regression pass. This release's multilingual work is word-lists and
lookup tables, not the name-morphology substrate aliases will need.

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).

No new runtime crates, no new config, no breaking changes. Warning-free.
