# Inkhaven 1.7.24 — Pre-1.8 Hardening

_A stability and performance pass over the linguistic layer ahead of 1.8. No new
features and nothing changes for the user; the internals are tightened. No new
runtime crates._

## Atomic writes

The linguistic layer's five store-write helpers — saving an interlinear text, a
hypothesis, a curated translation, a status change, and the shared chapter-paragraph
upsert — now write through `io_atomic` (temp file + rename) instead of a plain
`std::fs::write`. A crash mid-write can no longer leave a half-written `.typ`,
bringing this code up to the project's atomic-write standard.

## Corpus caching

In the Linguistic companion, the corpus is now built once per language and cached
for the session. Running `/frequency`, then `/kwic`, then `/coll` used to rescan the
entire manuscript and rebuild the gloss index each time; now the expensive pass runs
only when you switch languages. The manuscript scan also runs its conlang-context
check over the lazy word stream, so prose with no invented-language words is skipped
without materialising its tokens.

## Bounded minimal-pairs

`minimal_pairs` still counts functional load over every pair exactly, but the
collected sample is now bounded — a lexicon with an enormous number of minimal pairs
can't materialise them all in memory before the final truncation.

## Dependencies & compatibility

**No new runtime crates.** Internal-only — atomic writes, a session corpus cache in
the companion, and a memory bound on minimal-pairs collection; no behaviour changes,
no new or altered commands. Warning-free (binary and tests). Test suite → 2581.
