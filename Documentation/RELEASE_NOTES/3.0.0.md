# Inkhaven 3.0.0 — The Stable Edition

_Not a feature. A commitment._

3.0.0 closes the 2.x arc and promotes Inkhaven to a **stable, maintained edition**. The
intelligence suite — the book that watches, reads, and remembers itself — is complete.
From here the work is **maintenance: bug fixes and refinements to existing features, not new
ones.** This release is the line drawn under the surface that will be maintained.

## What "stable" meant, concretely

3.0.0 is the product of a deliberate hardening pass, not a feature sprint. The whole 2.x arc
(SEMNET → GRAPHMIND → CHORUS → SENTINEL → LECTOR → REDLINE → CHRONICLE → KEN) had never had a
full-source audit; before freezing the surface, it got one.

**A seven-partition adversarial audit** (storage, TUI, the analytical intelligences ×2, CLI &
the Bund sandbox, import/export parsers, research) swept 304K lines and found the codebase
**fundamentally sound**: zero Critical issues, and the highest-stakes surfaces verified clean —
the Bund sandbox policy is airtight, UTF-8/byte-slicing is airtight across five languages, the
panic surface is almost entirely guarded, untrusted parsers are proptested, and manuscript saves
are atomic and write the focused document.

**Every finding that survived verification was fixed:**

- **Correctness & data integrity** — the chronicle milestone write is now one transaction (no
  more a partial milestone reading as "findings cleared"); 14 feature stores gained a schema
  version anchor so a future binary can refuse an incompatible on-disk shape; the EPUB and
  WordNet writers are now atomic (`.part`+rename / temp+fsync) so an interrupted write can't
  destroy a good artifact; an untrusted PDF import is guarded against a parser panic that could
  tear down the research TUI.
- **Cost safety** — the utopia Stage-2 pass, which was quadratic in claims and could fire
  thousands of sequential paid LLM calls unstoppably, now refuses (before any call) above a
  configurable cap.
- **Performance at book scale** — the Output pane no longer runs a live database query every
  frame; a continuity pass that was accidentally quadratic is now linear; the ambient continuity
  watch no longer runs a full-book scan on the editor thread of a very large manuscript.
- **Sandbox & scripting** — a `ink.lang.names` denial-of-service (uncapped generation) is closed;
  the `ink.thread.list` word was reconciled with the CLI's actual data model.
- Plus a handful of smaller leaks, hangs, and help-text inaccuracies.

## The documentation is now the contract

A freeze makes the docs authoritative, so the coverage gaps were closed:

- **New feature docs** for the scholarly apparatus (`index-locorum` / `index-verborum` /
  `lexicon` / `argue`), the technical-documentation checks (`docs verify` / `links` / `review`),
  the reasoning-rigor reader, plot threads, and the back-of-book index — all previously
  documented only in release notes.
- **21 previously-undocumented configuration blocks** now specified field-by-field in
  `CONFIGURATION.md`, defaults copied from the code.
- **A canonical [`FEATURE_INDEX.md`](../FEATURE_INDEX.md)** — the definitive map of every
  feature to its CLI verb, editor chord, doc, and `ink.*` scripting namespace.
- The doc index and keybinding reference were completed to match the shipped surface.

## Compatibility

No breaking changes. Existing projects open unchanged; the new schema anchors stamp themselves on
first open. Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and **macOS**
(`aarch64-apple-darwin`).

## The shape of maintenance

3.0.0 is a promise about *restraint*, not stagnation. Bugs will be fixed, existing features
refined, the companion books kept current. New analytical axes — the next flagship in the mold of
KEN or LECTOR — are paused deliberately: the surface a single author already carries is large, and
every feature kept is a feature maintained. When that calculus changes, it will change on purpose.
