# Inkhaven 1.6.23 — Hardening & Foundations

_A stability release. It tightens the script sandbox, bounds an allocation
surface in language generation, and lays two reusable foundations for the work
ahead. No new features, no new runtime crates — the kind of release that makes
the next one safe to build. Test suite → 2470, warning-free._

## The script sandbox closes a gap

Inkhaven's Bund scripting runs under a policy that gates every verb by category
(`store_read`, `store_write`, `fs_write`, `net`, …) so a project's auto-loaded
scripts can be held to a conservative default. A verb that was **missing** from
the category table, though, was silently *allowed* — it slipped past whatever
categories you had disabled.

A new coverage test now enumerates every registered `ink.*` verb and requires
each to be **either** categorised **or** on an explicit pure-allowlist (verbs
that touch no protected resource — in-memory PDF-handle transforms and the
`ink.lang.dict` constructor). It immediately found **16 verbs** — the
timeline-critique operations, the Inner Socrates inspectors, and the world
fact-check timeline queries — that were reading the store outside the category
system. All 16 are now gated `store_read`, and a forgotten category on any
future verb fails the test rather than escaping the sandbox.

## Language generation can't be made to run away

The paradigm generator realises a word's full inflection from a morphology
spec. Two stem-growing processes — `full` reduplication (which *doubles* the
stem) and ablaut insertion rules (which multiply it) — could be listed any
number of times in a single cell, compounding as `2^N` / `64^N`. A crafted or
careless spec would exhaust memory the first time any paradigm generated —
which also drives glossing, reverse lookup and translation across every lexicon
entry.

Generation now caps the working stem at a generous bound (far past any natural
word) and stops reshaping once a spec runs away, finishing a bounded form
instead of exploding. The `poem` meter arithmetic is likewise saturating. An
adversarial audit of the rest of the language suite confirmed it already total
against panics.

## A cleaner Output filter

Reasoning-rigor findings (`⊬`) are now filterable by their own source in the
Output pane, alongside confront and locus findings, instead of falling into the
catch-all "other" group.

## Foundations for what's next

Two internal refactors, no behaviour change:

- A reusable full-screen-TUI shell (`tui_host`) — the terminal lifecycle and
  event loop the Research companion has always run, lifted into a shared,
  unit-tested module the next companion app builds on rather than forks.
- The companion tree-pane roots on any system book by tag, not just the Facts
  book — so a second pane can reuse it.

## Dependencies & compatibility

**No new runtime crates.** Everything is a hardening or internal change;
existing projects and scripts behave identically, except that the 16 newly-gated
verbs now honour a `store_read` denial if you had set one. The tree builds
warning-free (binary and tests). Test suite → 2470.
