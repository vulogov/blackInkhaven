# Inkhaven 1.8.15 — Poetry in Bund (POEM PO-P9)

_The poetry engines reach the Bund scripting language. Four `ink.poem.*` words let a script
syllabify, scan a line, classify a rhyme, and check a form's completion — all pure,
read-only, and default-allowed. **No new runtime crates.**_

## `ink.poem.*`

```
ink.poem.syllable_count  ( word lang -- n )
ink.poem.scan_line       ( line lang -- dict{pattern syllables metre} )
ink.poem.rhyme           ( word1 word2 lang -- dict{quality type shared note?} )
ink.poem.status          ( text form lang -- dict{lines expected complete issues} )
```

Each is a thin wrapper over a POEM engine (the syllabifier, metre scanner, rhyme engine,
and form checker), so a Bund hook or custom rule can reach the same analysis the CLI and
the Inner Poet use. Every `ink.poem.X` also answers to the shorter `poem.X`.

All four are **`store_read`** — pure and default-allowed, needing no store and no granted
category. The RFC's store-writing words (`suppress` / `set_form`) and the store-reading
`findings` / open-paragraph `form` lookup ride with the deferred `inner_poet.db` store.

## Dependencies & compatibility

**No new runtime crates.** A new `scripting::stdlib::poetry` module (four words) and their
`store_read` policy entries, composing the existing POEM engines. Warning-free (binary and
tests). Test suite → 2653.
