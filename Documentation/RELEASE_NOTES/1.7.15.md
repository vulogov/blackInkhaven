# Inkhaven 1.7.15 — The Segmentation Line

_The first interlinear slice glossed each word as a whole; this one splits it. IGT's
top line is now the true Leipzig morpheme segmentation — `kata-t` over `stone-DAT` —
with the boundaries recovered even when allophony has reshaped an affix at the
seam. No new runtime crates._

## Morpheme segmentation, aligned to the gloss

`igt` now shows the morpheme-segmented sentence on line 1, split at every affix
boundary and aligned morpheme-for-morpheme with the gloss:

```sh
inkhaven language igt Eldar --text "katat nilo"
```

```
kata-t     nilo
stone-DAT  friend
'stone friend'
```

The hard part is that an affix's surface can change at the boundary: a dative
*kata + d* surfaces as *katat* once the language's allophony devoices the final
consonant. IGT gets it right — paradigm generation now tracks each morpheme's span
in the underlying form and re-slices the *surface* at those spans after allophony
runs, so the dative is segmented `-t`, not `-d`. When an allophony rule inserts or
deletes segments (so the spans no longer line up), the word degrades gracefully to
an unsegmented single piece rather than mis-splitting.

The stem — a root plus any non-concatenative morphemes (ablaut, reduplication) — is
a single segment, since those processes have no clean linear boundary. This applies
everywhere an interlinear is shown: the `igt` verb, the `/igt` companion command,
and the structured `--json` output.

## Dependencies & compatibility

**No new runtime crates.** Additive — `paradigm::generate` gains a `segments` field
on each row (its one construction site), threaded through the gloss index into IGT;
existing forms and glosses are unchanged. Warning-free (binary and tests). Test
suite → 2566.
