# Inkhaven 1.3.34 — The review pass, and where the money goes

_Two road-to-1.4.0 consolidation features. **`inkhaven check`** is the unified review
pass: one gesture runs every fast checker over a scope and lights up the manuscript
with where attention is needed. The **AI cost dashboard** is one place to see today's
LLM spend — now tracking **every** inference, not just the capped slow tracks — and
it follows the house rule that cost control should **inform, not gate**. Both are
pure additions over existing infrastructure; zero new dependencies._

## The unified review pass

Each checker used to be its own command. **`Ctrl+B Shift+C`** (or `inkhaven check`)
now runs them all at once:

- the **world fact-checker** + **Inner Socrates** over the open paragraph,
- the **timeline critique** over the project,

all into the **Output pane** — where the 1.3.33 filtering (`f`/`S`/`t`) slices the
combined findings — with a `fact N · socrates N · timeline N` summary. Instant and
LLM-free.

And the manuscript shows you **where** to look: each tree node carries a
**report-card badge** (`⊗`/`⚠`/`●` + count) for the open findings under it,
aggregated up from the source paragraphs and colored by the worst severity. The
count drops as you dismiss findings.

CLI: `inkhaven check [--paragraph … | --book-name …] [--no-fact | --no-socrates |
--no-timeline]` prints the same findings grouped + a per-checker summary.

## The AI cost dashboard

**`Ctrl+B $`** (or `inkhaven cost`) opens one view of today's LLM usage:

- **Daily budgets** (the cost-capped slow tracks) with a usage bar.
- **Other AI calls today**, by category — chat, grammar, explain, critique,
  continuation, translation, and the rest. Every inference is now recorded at the
  one chokepoint it flows through, so this is the *whole* picture, not just the
  capped tracks.
- Today's total.

The counts are **per calendar day (UTC)** and reset at 00:00 UTC. The dashboard is
extensible: any future analytical thread that records a slow pass under its own
sub-budget appears automatically.

### Cost control informs; it does not gate

Following Inkhaven's design principle — a permissive individual tool, restricting
only for security — **the daily caps no longer block.** Past a daily budget the
slow tracks **warn and continue**; the author decides. The dashboard says so
plainly: *"Budgets are informative, not limits."*

## Dependencies & compatibility

**No external application or binary dependencies; no new runtime crates.** Both
features are read-side views/orchestration over existing checkers and stores. The
one behavioural change is making the previously-blocking daily slow-track cap a
warning. Tests 1795 → 1804.
