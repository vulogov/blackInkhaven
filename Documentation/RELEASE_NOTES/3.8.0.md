# Inkhaven 3.8.0 — A Quieter Editor, a Sharper Tree

_Two TUI tracks. **Rendering & responsiveness** stops the editor burning CPU
when idle, finishes the matching-bracket feature, lines up the cursor on wide
(CJK) text, and makes the theme survive monochrome and light terminals. **The
Tree pane** grows an in-tree filter, branch word-count roll-ups, chapter
jumps, bookmark markers, and a key-legend footer. From the same TUI focus as
3.7.0 — no new reader or axis._

Deterministic, no **new** runtime crates (the one added dependency was already
in the tree), warning-free; the suite grew to **3017**.

---

# Rendering & responsiveness

## Idle-redraw dirty flag — the flagship

The main loop redrew the **whole frame ~5×/second even when nothing changed** —
rebuilding the syntax-highlight vectors, the style-warning scans, and a
full-book scan for the editor title, five times a second, forever. Over SSH or
on a laptop that's pure wasted CPU (a long-standing item, deferred since the
pre-1.9 hardening audit).

Now the loop draws only when something actually changed (a keypress, a resize, a
tick that updated the status line), an **animation is live** (streaming tokens,
the reader-pace teleprompter, a running background job → fast redraws), or a
**~1-second backstop** expires. An idle editor rebuilds the frame ~once a second
instead of ~five times. The backstop guarantees the screen never goes stale
beyond ~1 s even if a redraw trigger is ever missed — a forgotten flag degrades
to a 1 s lag, never a frozen UI. Input still wakes the loop instantly.

## Matching-bracket highlight

3.7.0 shipped `Ctrl+Z m` (jump to the matching bracket); 3.8.0 adds the other
half: whenever the cursor sits on (or just after) a bracket, **both it and its
partner are underlined** — across lines, respecting nesting. Applied in both
editor render paths (wrapped and unwrapped), so it shows regardless of your wrap
setting. Cheap: one match-scan per frame, and with the dirty flag it only
recomputes when the frame actually redraws.

## Wide-character (CJK) columns line up

The editor treated one character as one terminal cell, so past a wide (CJK) or
emoji character the **cursor drifted** off its glyph, **clicks mislanded**, and
long lines wrapped by character count (overflowing the pane). The cursor
placement, click-to-position, and line-wrapping are now **display-width aware** —
a CJK char counts as two cells, a combining mark as zero. Transparent for
one-cell scripts (Latin, Cyrillic): every change reduces to the old
character-count math, so the common case is provably unchanged.

## Theme survives monochrome and light terminals

- **`NO_COLOR` is honored** (the [no-color.org](https://no-color.org)
  convention): set it and every theme colour resolves to the terminal default,
  for monochrome / accessibility / light-background terminals. Structure still
  reads via the bold / reversed / underlined modifiers.
- A **hardcoded dark-grey code-block background** in the markdown renderer (Help
  book, AI responses) — a fixed 256-palette colour that stayed an invisible dark
  box on a light terminal — is gone; the adaptive colours it uses elsewhere read
  on any background.

# The Tree pane

A focused pass on the left-hand navigation pane — every item rides data or a
pattern that already existed elsewhere in the app.

## In-tree filter (`/`)

The tree had no search: in a long book you scrolled. Press **`/`** and type — the
tree narrows live to nodes whose **title or slug matches** (case-insensitive,
Unicode-aware) plus their ancestors, so context survives. `Enter` keeps the
filter with the cursor on the first match; `Esc` clears it. The active needle
shows in the pane title. This is the same pruned path-to-match view the Outline
pane already uses, brought to the tree.

## Branch word-count roll-up

`word_count` lives on every node, but a chapter never told you how long it was.
Now **Book / Chapter / Subchapter rows show their aggregate descendant word
count** (compact — `12.3k`), plus a **roll-up progress pip** when the subtree
carries any target-word goals. Paragraph-level counts and pips are unchanged.

## Jump-by-kind (`{` / `}`)

**`{`** and **`}`** move the cursor to the previous / next **major structural
row** (Book or Chapter), skipping past long paragraph runs. Stops at the
first/last with a status hint; no wrap.

## Bookmark markers

Paragraphs flagged with `Ctrl+V B` now show a **flag glyph** in the tree, so
bookmarked rows are visible while you navigate (the jump itself stays in the
`Ctrl+V M` bookmark picker).

## Key-legend footer

The tree pane's bottom line now carries a dimmed, **mode-aware key legend**
(`b/c/a add · d/- del · u/j move · z/x fold · {} chap · / find`, and dedicated
hints while filtering) — extending to the tree the dashboard-footer treatment
the rest of the TUI got in 3.7.0.

## Deferred as follow-ups

Still deferred: a full hand-tuned **light palette preset** (`NO_COLOR` covers the
readable-on-light case for now), OSC-11 light-background auto-detection, the
*unwrapped* path's horizontal-scroll wide-char edge (rare; the default wrapped
path is fully consistent), and the per-active-frame draw optimizations
(viewport-only draw / cache-borrow — the idle-redraw flag handles the idle case,
which was the bulk of the cost).

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).

No new config, no new runtime crates (`unicode-width` was already transitive), no
breaking changes. Warning-free.
