# Inkhaven 3.8.0 — Rendering & Responsiveness

_The second TUI-focused release: it stops the editor burning CPU when idle,
finishes the matching-bracket feature, lines up the cursor on wide (CJK) text,
and makes the theme survive monochrome and light terminals. From the same TUI
audit as 3.7.0 — no new reader or axis._

One track, four items. Deterministic, no **new** runtime crates (the one added
dependency was already in the tree), warning-free; the suite grew to **3013**.

## Idle-redraw dirty flag — the flagship

The main loop redrew the **whole frame ~5×/second even when nothing changed** —
rebuilding the syntax-highlight vectors, the style-warning scans, and a
full-book scan for the editor title, five times a second, forever. Over SSH or
on a laptop that's pure wasted CPU (a long-standing item, deferred since the
pre-1.9 hardening audit).

Now the loop draws only when something actually changed (a keypress, a resize, a
tick that updated the status line), an **animation is live** (streaming tokens,
the reader-pace teleprompter, a running background job → fast redraws), or a
**~1-second backstop** expires. An idle editor rebuilds the frame ~once a second
instead of ~five times. The backstop guarantees the screen never goes stale
beyond ~1 s even if a redraw trigger is ever missed — a forgotten flag degrades
to a 1 s lag, never a frozen UI. Input still wakes the loop instantly.

## Matching-bracket highlight

3.7.0 shipped `Ctrl+Z m` (jump to the matching bracket); 3.8.0 adds the other
half: whenever the cursor sits on (or just after) a bracket, **both it and its
partner are underlined** — across lines, respecting nesting. Applied in both
editor render paths (wrapped and unwrapped), so it shows regardless of your wrap
setting. Cheap: one match-scan per frame, and with the dirty flag it only
recomputes when the frame actually redraws.

## Wide-character (CJK) columns line up

The editor treated one character as one terminal cell, so past a wide (CJK) or
emoji character the **cursor drifted** off its glyph, **clicks mislanded**, and
long lines wrapped by character count (overflowing the pane). The cursor
placement, click-to-position, and line-wrapping are now **display-width aware** —
a CJK char counts as two cells, a combining mark as zero. Transparent for
one-cell scripts (Latin, Cyrillic): every change reduces to the old
character-count math, so the common case is provably unchanged.

## Theme survives monochrome and light terminals

- **`NO_COLOR` is honored** (the [no-color.org](https://no-color.org)
  convention): set it and every theme colour resolves to the terminal default,
  for monochrome / accessibility / light-background terminals. Structure still
  reads via the bold / reversed / underlined modifiers.
- A **hardcoded dark-grey code-block background** in the markdown renderer (Help
  book, AI responses) — a fixed 256-palette colour that stayed an invisible dark
  box on a light terminal — is gone; the adaptive colours it uses elsewhere read
  on any background.

## Deferred as follow-ups

The always-on bracket highlight ships; still deferred: a full hand-tuned **light
palette preset** (`NO_COLOR` covers the readable-on-light case for now), OSC-11
light-background auto-detection, the *unwrapped* path's horizontal-scroll
wide-char edge (rare; the default wrapped path is fully consistent), and the
per-active-frame draw optimizations (viewport-only draw / cache-borrow — the
idle-redraw flag handles the idle case, which was the bulk of the cost).

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).
