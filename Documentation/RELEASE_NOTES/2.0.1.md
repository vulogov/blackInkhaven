# Inkhaven 2.0.1 — GRAPHMIND: Chat with Your Graph

_2.0 gave your project a knowledge graph — a typed-edge layer connecting every node into
one interrogable whole. 2.0.1 gives that graph a **mind**: it fills itself as you research,
and you can **talk to it**. Ask how your book connects — what contradicts what, what
grounds a claim, how a scene is sourced — and the model answers from the relations, not
just the prose._

The flagship of 2.0.1 is **GRAPHMIND**, the AI partner over the SEMNET graph. It has two
halves: the graph **builds itself** (deep research and fact-work propose typed stance edges
you triage), and you **interrogate it** (a Graph AI scope, a `graph ask` traversal loop,
and a streamed in-editor graph walk). It builds almost entirely on 2.0's edge layer and the
existing Book-RAG machinery — the citation contract, the retrieval, the agentic-loop idiom —
so it is mostly wiring, not new substrate, and no new runtime crates.

## The graph builds itself (Part A)

- **Deep research persists contradictions.** The agentic research loop (`research --agentic`)
  now lands the clashes it detects as `Contradicts` edges in the graph — deep research
  leaves a connected subgraph behind, not just Facts paragraphs.
- **`inkhaven graph link <node>`** — the confront judge over your own corpus: retrieve a
  fact's nearest related facts, grade each relation, and persist the non-silent ones as
  advisory `judged` stance edges (node→node). Explicit and on-demand, so it never freezes an
  insert or surprises you with cost.
- **The edge inbox.** Advisory `judged` edges (from confront, `graph link`, deep research)
  collect in one place to triage: **`inkhaven graph pending`** on the CLI, or in the editor
  the new **graph hub `Ctrl+B z`** → **`i`** — where **`P`** promotes an edge (kept across
  `graph rebuild`) and **`d`** rejects it. (The hub also fixes a 2.0.0 bug: the neighbourhood
  chord shipped dead, shadowed by another binding — it now lives at `Ctrl+B z → n`.)

## Chat with your graph (Part B)

- **The Graph AI scope (F9 → Graph).** The relational sibling of Book scope: it retrieves
  the passages relevant to your question and folds in the graph edges touching each — what it
  contradicts, is sourced from, links to, cites — so the answer is grounded in how the book
  *connects*. Sticky like Facts; reuses the Book-RAG citation contract verbatim (invented
  citations are flagged). Press **`p`** to see the retrieved passages + their relations.
- **`inkhaven graph ask "<question>"`.** Answers by *walking* the graph: the model searches
  for seed nodes, then queries neighbours / contradictions / loci / paths turn by turn until
  it can answer — grounding the answer in what it observed, and honest about the graph's
  limits (it says "the graph doesn't record that" rather than inventing a link). The
  exploration transcript prints to stderr, the answer to stdout.
- **The in-editor graph walk (`Ctrl+B z → w`).** The same traversal, streamed and
  non-blocking, inside the editor: type a question, and the AI pane shows the model walk your
  graph live — each step (search → neighbours → contradictions → paths) — then streams the
  grounded prose answer as a chat turn. **`Esc`** stops the walk; the status bar shows
  `turn k/N`. All graph access stays on the UI thread — no background thread, no second store
  handle — so the crash-safety guarantees hold.

Multilingual throughout (EN/RU/ES/FR/DE grounding + tool contracts). Bounded and tunable by
a new `graph` config block (`ask_max_steps`, `ask_search_width`) — per the permissive
principle, these inform and cap cost, they never block. A walk is opt-in (several model
calls), so the light one-hop Graph scope stays the default and you choose the depth per
question. Graph-AI calls are tagged `graph_rag` in the cost dashboard.

## Also in 2.0.1

- **The 2.0 readiness gate is closed honestly.** A dedicated long **soak** (171k iterations —
  node CRUD + edge insert/query/cascade + periodic embeds + integrity checks) confirmed no
  leak and a consistent store; a fresh full-codebase **multi-agent panic audit** confirmed
  zero reachable panics.
- **Fix: the edge-store integrity check** ran a `PRAGMA integrity_check` DuckDB doesn't have,
  so it errored on every call and false-warned the health monitor. It now enumerates tables
  via `information_schema` and full-scans each — surfaced by the soak itself.
- Documentation + companion books updated for the new surfaces (`GRAPH.md`, `CONFIGURATION.md`,
  `KEYBINDING.md`, the CLI-reference and manual chapters).

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and **macOS**
(`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX bindings ship no
windows-gnu prebuilt).
