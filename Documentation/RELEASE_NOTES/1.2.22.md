## Highest-value candidates (still open)

### Cross-book find-and-replace (the standout)

Still the biggest gap for a working novelist: find/replace works only on
the open paragraph; the concordance is read-only.  **Renaming a
character across every chapter** is the most common structural edit and
the tool can't do it.  Fits the store-walk + doctor-scan + snapshot
machinery for safe bulk mutation (preview diff, snapshot every touched
paragraph before applying).  On-theme for a *revision* product.

### "Publishable book" — front-matter

Title page, copyright / colophon, optional ToC for the PDF (and ePub).
The PDF compiles via typst but emits no title page.  Pairs with the
1.2.20 ePub cover into a "make the export a finished book" theme.

### Spell-check

A genuine absence (F7 is LLM grammar-check, no dictionary spell-check).
Heavier — a dep + per-language dictionaries (hunspell); weigh against the
dep budget.

## Theme candidates

### Genre packs (now more attractive)

1.2.21's `facts init --genre` is a first taste.  A genre-packs cycle:
mystery + historical-fiction project templates + style-rule packs (clue
tracker, fair-play audit, the anachronism overlay), building on the
Facts genre scaffolds.

### Dialogue & voice

* Character voice consistency (does X speak in their established voice
  here?), grounded in the Characters book.
* Dialogue-ratio gauge (% dialogue vs narration).
* Dialogue-tag detector (said-bookisms, adverb-laden tags, overuse).
* Per-character verbal-tic report.

### AI maturity

Multi-paragraph envelope (±1 paragraph), hot-reload `prompts.hjson`, AI
streaming into the editor at the cursor.

### Finishing & submission

Query-letter + synopsis AI helpers (RAG-grounded), front/back-matter
nodes (dedication, acknowledgments, copyright), full-book read mode.

## Facts follow-ups (parked from 1.2.21)

* **Internal-consistency check** of the Facts book against *itself*
  (catch facts that contradict each other before they hit the prose).
* **Multi-book / series-shared facts** (a facts library across books).
* **Link-type annotations** (source / verified / contradiction) on the
  wiki-link model — would need `linked_paragraphs: Vec<(Uuid, LinkType)>`.
* **Embedding-based dedup** for `facts extract` (vs the current
  stemmer-token Jaccard), and embedding-aware contradiction in the scan.
* A deterministic (non-AI) contradiction pass — would need optional
  structured facts (a tagged `#key value` line, the way Threads front
  HJSON).  Decide the free-form-vs-structure question first.
