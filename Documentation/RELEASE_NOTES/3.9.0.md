# Inkhaven 3.9.0 — Panes That Keep Up

_The third TUI pass finishes the pane-polish arc and then goes deeper on the one
surface a working author lives in — the AI pane. **Polish:** the AI, Search, and
Thoughts panes get the treatment the Tree and Output panes got in 3.8. **Depth:**
the AI pane and its prompt grow the things you reach for daily — a multi-line
compose box, retry / edit-and-resend, citations you can follow into the book, and
a library of saved conversations. No new reader or axis._

Two tracks, nine items. Deterministic, no new runtime crates, warning-free; the
suite grew to **3029**.

# The AI pane grows up

Beyond the polish below, the AI pane and its prompt gained four capabilities a
chat surface is expected to have.

## A multi-line compose box

The prompt was a **single line** that *flattened* pasted newlines to spaces — so
a detailed, structured instruction (or a pasted excerpt) was impossible to
compose faithfully. Now the box is multi-line: **`Shift+Enter`** (or `Alt+Enter`)
inserts a newline, plain `Enter` still sends, and a **paste keeps its newlines**.
The box **grows** to fit what you type and **collapses back to one line** when
it's empty — so it stays out of the way until you need the room. `Up`/`Down` move
between lines, falling through to prompt-history recall at the first/last line.
(The single-line search bar and modal inputs are untouched.)

## Retry and edit-and-resend

There was **no way to redo a reply**. Now, in the AI pane, **`z` regenerates**
the last response (re-sends the same prompt under the current scope) and **`e`
pulls the last prompt back** into the compose box to tweak and resend. Both act on
the last exchange whenever the chat ends with a completed turn.

## Citations you can follow

Book-scope answers cite `[chapter/scene]` locations that were **inert text**. Now
**`[` / `]` jump to the previous / next cited paragraph** — in the order the
answer cites them — opening each in the editor (falling back to the direct
semantic hits when the answer cited nothing explicitly). A grounded answer becomes
a reading path into the manuscript. A `[ ] cited ¶` cue shows in the title.

## A conversation library

Chat persisted as a single auto-file with no way to keep or name threads.
**`Ctrl+Z l`** opens the conversation library: **`Enter`** reopens a saved thread,
**`s`** saves the current one (auto-named from its first prompt), **`d`** deletes,
**`n`** starts a new one. Threads live under `.inkhaven/conversations/`, so a line
of thinking survives the next clear.

# Pane polish

## The AI response follows the stream — and you can stop it

The split-view AI response (the common `scope ≠ Book` case) had **no scroll at
all**: a long or streaming reply could only ever show the top pane-height lines,
and the newest tokens streamed below the fold, unreadable until you fullscreened.

- **Scroll + follow-while-streaming — the flagship.** The response now scrolls,
  and by default **follows the streaming tail** as it grows (a `⟳follow` cue in
  the title). Scroll back with `↑`/`k`/`PgUp`/`Home` and it detaches
  (`↑scrolled`); `End` re-arms follow and jumps to the newest. Wired to the
  mouse wheel too. Modelled on the fullscreen chat's distance-from-bottom scroll,
  so `0` always means "pinned to newest."
- **A genuine cancel.** `Esc` now **cancels an in-flight inference** — from the AI
  pane or the prompt — stopping the stream and keeping the conversation. (The
  background task abandons the provider call the moment its receiver drops.)
  Previously the only stop was `Ctrl+B c`, which wipes the *whole* chat; that
  still exists for when you want it. The title shows an `Esc cancel` cue while
  streaming.

## The search bar remembers, and the results overlay scrolls

- **Query-history recall.** The Search bar was the only one of the three text
  inputs without history. `↑`/`↓` now walk your prior queries, shell-style —
  the same recall the AI prompt and F1 help query already had. The focused title
  shows a `↑ history` cue.
- **A results overlay that scrolls and pages.** The overlay rendered every hit
  into a non-scrolling box clamped to the terminal, so on a short window lower
  results — and an off-screen cursor — were unreachable. It now **scrolls the
  selected result into view**, with `PgUp`/`PgDn` and `Home`/`End` paging, and
  the result cap is lifted **10 → 50** now that the list is navigable.

## The Thoughts pane, liftable and fully reachable

- **Copy-out.** `y` yanks the whole reflective transcript (Inner Theologian
  sessions and the like) to the system clipboard — it had no copy affordance,
  and `c` is a *destructive clear*.
- **The bottom is reachable again.** `G`/`End` could stop short of the last few
  lines because the scroll clamp counted wrapped rows by character width
  (under-counting vs the word-wrap ratatui actually draws); it now counts with
  the same greedy word-wrap. Plus a stale scroll-direction comment fixed.

## Deferred as follow-ups

Per-turn copy in the split Book-conversation view (fullscreen selection mode
already copies), incremental/as-you-type search, and a scroll offset independent
of the selection. None blocks the everyday flow.
