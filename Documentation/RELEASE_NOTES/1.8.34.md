# Inkhaven 1.8.34 — Pre-Major Hardening

_A full-source, six-agent audit ahead of the next major, and the fixes for everything it
turned up. The codebase was already sound — no reachable panics, the 1.2.15 stability bar
holding — so this release is the MEDIUM-tier fix list: a DoS, a silently-failing gate, three
non-ASCII data bugs, several non-atomic writes, an untrusted-input stack overflow, a poetry
accuracy gap, and the last of the per-frame editor costs. Every fix ships with a regression
test._

## Correctness & safety

- **`/calc` no longer freezes on a huge factorial.** `1e15 calc.factorial` saturated an
  integer cast and spun ~10¹⁹ iterations on the synchronous calculator thread — an unkillable
  hang. 171! already overflows to infinity, so it now short-circuits.
- **The research confidence gate no longer fails open.** `parse_confidence` grabbed the first
  digit run and clamped it, so `"90% confident"` or `"In 1918…"` both scored 1.0 and passed the
  `--auto-confirm` / `--agentic` insert threshold. It now accepts only a genuine 0–1 probability
  and rejects bare integers (fail closed).
- **Non-ASCII is preserved on import and export.** Markdown export Latin-1-decoded UTF-8 to
  mojibake; Scrivener `.rtf` import flattened raw Cyrillic/accented prose to `?`. Both now keep
  the characters (the RTF path routes raw-UTF-8 projects to the content-preserving fallback).
- **Deeply-nested Scrivener projects can't crash the importer.** A pathological `.scrivx` built
  a binder tree whose recursive walk and drop overflowed the stack; nesting is now capped
  (items past the cap are dropped with a warning, never silently).

## Durability

- **Atomic writes for everything that matters.** The on-disk source-of-truth **World** leaves
  (`commit`/`materialize`), the **backup** archive, and **export** artifacts (`.md`/`.tex`/
  `.epub` and the bundle zip) all wrote in place — an interruption could leave a truncated file
  where a good one used to be. They now write to a temp/`.part` and rename on success.

## Poetry

- **Metre scanning consults the English pronouncing dictionary.** The scanner resolved English
  stress from a crude penultimate rule and never used the phoneme dictionary — so final-stressed
  words (`compare`, `begin`, `above`, `return`) mis-scanned. It now uses the dictionary's exact
  stress when installed, with an explicit acute mark still overriding. This closes, for metre,
  the English-scansion limitation the dictionary had already closed for rhyme and syllable count.

## Editor performance & concurrency

- **The idle editor frame now does no repeated work.** The style-warning **banned-synonym
  detector** was rebuilt on every repaint — a blocking filesystem read per Glossary paragraph
  (~1000 reads/sec with a large glossary, whenever style warnings were on). It's now cached and
  invalidated only when the tree reloads. Together with the highlight, lexicon, and POV-chip
  caches from 1.8.32–1.8.33, an idle frame re-parses, re-stems, re-scans, and re-reads nothing.
- **Inner-Editor engagement reuses shared store handles.** The engage worker opened
  `inner_editor.db`, `inner_socrates.db`, and (via grounding) the **main** project store afresh
  while holding them across its LLM call — colliding with the UI's own opens (transient stale
  badges). It now reuses the App-held handles.
- **The background vector-index sync no longer piles up threads.** A burst of saves spawned one
  detached sync thread each; it's now gated to a single coalescing thread.

## Dependencies & compatibility

No new dependencies (crate or binary). Compiles warning-free. Test suite → 2676 (fixes come with
regression tests over the confidence gate, the non-ASCII paths, the metre dictionary, and the
binder depth cap). One inherent item remains documented: the background vector sync still holds
the store lock across the index serialize, so a back-to-back save can still wait on it — fully
addressing it needs a snapshot-under-lock API or the event-driven redraw planned for a later
release.
