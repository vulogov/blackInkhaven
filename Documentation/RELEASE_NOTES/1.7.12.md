# Inkhaven 1.7.12 — Ablaut

_The parser has learned to reverse concatenative affixes, then full reduplication,
then partial. This release adds the last non-concatenative process: ablaut — the
internal vowel change of *sing/sang/sung*. With it, the morphological parser now
undoes every process the generator can apply. No new runtime crates._

## Ablaut in the parser

Ablaut inflects a word by changing a vowel *inside* the stem rather than adding
anything to its edges — English *foot/feet*, *drink/drank*, or a conlang whose past
tense rewrites `a → i` so *kat* becomes *kit*. Because an in-place rewrite is not
generally reversible (the rule can be context-sensitive or class-based), the parser
does not try to invert it. Instead it runs *generate-and-test*: at the start of a
parse it pushes every dictionary root forward through each ablaut morpheme's rules
and indexes the result, so a stem that matches an ablaut image is analysed as that
root plus the ablaut gloss:

```sh
inkhaven language parse Eldar --word kit     # → kat + PST
inkhaven language parse Eldar --word kiti     # → kat + PST + PL
```

It composes with ordinary affixes, and it surfaces everywhere the parser does — the
CLI, the companion's `/parse`, and the Oracle's morphological level.

## The parser is complete

With ablaut, the morphological parser now reverses **every** process the generator
applies: concatenative affixes (prefix, suffix, infix, circumfix), full and partial
reduplication, and ablaut. Any form the paradigm engine can build, the parser can
take apart.

## Dependencies & compatibility

**No new runtime crates.** Purely additive — a precompute in `parse` reusing the
existing forward rewriter (`rewrite::apply_ordered`); existing analyses are
unchanged, and a morphology with no ablaut morphemes is unaffected. The companion
book notes it in the parser's description. Warning-free (binary and tests). Test
suite → 2555.
