# Inkhaven 1.7.13 — Agreement, Generalised

_The clause Oracle could check that a verb agrees with its subject. That machinery
was hard-wired to one pair; it is now general. The Oracle checks agreement over
*any* head–dependent pair — an adjective with its noun, a determiner with its noun,
a verb with its subject — under whatever agreement rules the language declares. This
completes Wave 3's Oracle. No new runtime crates._

## Agreement over any head–dependent pair

Agreement is not only subject–verb. In many languages an adjective takes its noun's
number and gender, a determiner echoes its noun, a possessor agrees with its
possessum. The Oracle now checks all of them the same way: given a dependent word,
its root, and its head's features, it looks up the language's agreement rule for
that dependent, regenerates the form the rule *should* produce, and flags the
observed form if it differs:

```sh
inkhaven language check-agreement Eldar --dependent adjective \
  --form mira --root mira --head-features "number=pl"
#   ✗ [agreement] adjective `mira` does not agree with its head — expected `mirai` (adjective-PL)
```

The subject–verb check from 1.7.8 is now just one application of this general
engine — `check-clause` calls it for the verb, and the new `check-agreement` verb
opens it to every other dependent. When a language declares no agreement rule for a
dependent, the check is silent (there is nothing to enforce).

## Dependencies & compatibility

**No new runtime crates.** Purely additive — `oracle::check_agreement` generalises
the existing subject–verb logic (which now calls it, unchanged in behaviour) and a
new `language check-agreement` verb wraps it. Existing projects, languages and CLI
verbs are unchanged. The companion book documents the verb. Warning-free (binary and
tests). Test suite → 2558.
