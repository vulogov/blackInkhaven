# Inkhaven 3.2.0 — ENSEMBLE: Your Cast, Connected

_You've declared who knows what (KEN), who's bonded to whom (BONDS), and where
each arc bends (CHAR-1). 3.2.0 stops treating those as separate findings and lets
you **see the people** — the cast, their relationships, and their arcs — as one
connected picture._

3.2.0 is a **deepening**, not a new reader. It adds no findings; instead it makes
the *people layer* the existing readers already feed into something you can see
and traverse. Two pieces, both built straight on BONDS + the knowledge graph +
the CHAR-1 store — deterministic, ≈ $0, no new subsystem, no new runtime crates.

## 1 · Relationships on the graph

Every declared bond becomes a first-class **graph edge**. On `inkhaven graph
rebuild`, each `rel:<kind>:<A>:<B>` tag is promoted into a symmetric **`relates`**
edge between the two characters' nodes — the bond kind (ally / enemy / …) and the
first chapter riding in the edge, deduped to one edge per (pair, kind) so a
transition (`ally` → `enemy`) shows as two edges (both relationship states on the
graph). Because relationships are now edges, the whole existing graph stack reads
them for free:

- `inkhaven graph neighbors <char-node>` / `graph paths` traverse them;
- the **`Ctrl+B z`** graph hub → `n` renders a bond legibly (`⇄ Kell — ally (ch.
  1)`);
- the **F9 Graph** chat / `graph ask` can reason over them ("how are Mara and
  Sella connected?").

New edge kind `relates`; the bond kind + chapter live in the edge's `attrs`, and a
human `reason` renders in every neighbourhood view. See `GRAPH.md`.

## 2 · The Dramatis Personae

One book-wide view of the cast — **who is in this book, how they connect, and
where each arc stands** — joining three things inkhaven already tracks: the
**cast** (the roster), their **bonds** (BONDS `rel:` declarations), and their
**arc state** (CHAR-1: declared shape + latest observed chapter state + change
count + agency).

```
inkhaven cast          # the Dramatis Personae (human)
inkhaven cast --json   # the whole structure
```

```
Dramatis Personae — The Ninth Lantern (4 character(s))

Mara  [corruption · broken (ch. 5) · ✦1]
  ⇄ Kell — ally (ch. 1)
  ⇄ Sella — enemy (ch. 3)
```

The cast is the union of everyone the book *tracks* — anyone with an arc
declaration, a recorded state, or a declared bond — so a character who only ever
appears in a `rel:` tag still shows (nodeless, no arc). In the editor, the
**`Ctrl+B z` graph hub → `c`** opens it as a scrollable dashboard; **Enter** jumps
to a character's bible node. (It lives on the hub beside the relationship graph,
so no scarce top-level chord was spent.)

## Cost — a design invariant

ENSEMBLE writes no new model call. The relationship graph is derived edges rebuilt
with the rest of the graph; the Dramatis Personae is a pure join over data already
on disk. ≈ $0, deterministic, independent of book length.

## Scope, honestly

Of the three "deepen the people layer" pieces considered, two shipped: the
relationship graph and the Dramatis Personae — the low-risk, native surfaces.
**Alias resolution** (nicknames/titles resolving to a character across every
reader) was deliberately deferred: it touches the shared mention-matcher that five
readers depend on, and belongs in its own release with a proper regression pass. A
character is still matched by their roster name for now.

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).
