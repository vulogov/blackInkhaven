# Inkhaven 1.8.10 — The Rhyme Engine (POEM-4, PO-P4)

_Classify the rhyme between two words — its quality (perfect / near) and type (masculine /
feminine / dactylic) — across the five languages, each with its own tradition. The last
engine before the Inner Poet composes them. **No new runtime crates.**_

## Classifying a rhyme

`inkhaven poetry rhyme <word1> <word2>` reports the rhyme, keyed off the syllabifier and
each language's rules:

```sh
inkhaven poetry rhyme дом том --language ru      # perfect masculine rhyme on "-ом"
inkhaven poetry rhyme мо́ре го́ре --language ru   # perfect feminine rhyme on "-оре"
inkhaven poetry rhyme Hund bunt --language de     # perfect masculine rhyme on "-unt"
inkhaven poetry rhyme cielo viejo --language es   # near feminine (assonant rhyme)
inkhaven poetry rhyme light night --language en   # perfect masculine rhyme on "-ight"
```

The rhyme runs from the **stressed vowel** to the end of the word (using an acute mark where
present, else the syllabifier's rule). Each language normalizes its tail: German applies
**final devoicing** so *Hund* and *bunt* rhyme on `-unt`; French elides the mute *e*; Spanish
recognizes **assonance** (vowel-only matches); Russian applies light vowel reduction.

## Honest about its limits

Without a phonemic transcription for the natural languages, the engine works on the
orthographic rhyme tail. This is accurate for the regular orthographies — Russian above all
— but it can't tell an English *eye-rhyme* (`love`/`prove`, same spelling, different sound)
from a true rhyme. That, like the English metre accuracy, waits on the lexical phoneme
dictionary (a later refinement). Conlang rhyme, when it lands, will use the declared phoneme
inventory directly and need no such approximation.
