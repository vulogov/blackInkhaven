# Inkhaven 1.2.19 — (planning)

_1.2.19 is in scoping.  This document is a
scratchpad for carryovers + candidate themes;
the structure mirrors prior release notes so the
final write-up can be derived from it._

## Carryovers from 1.2.18

### R.1.b — ePub polish

R.1 shipped a valid, well-formed EPUB 3.  Polish
deferred:

* **Cover image** — embed a cover (from a
  configured path or the book's first Image
  node) as the EPUB cover + nav landmark.
* **Inline images** — carry Image nodes into the
  chapter XHTML (`<img>` + the blob) instead of
  skipping them.
* **Popup footnotes** — render `#footnote[…]` as
  proper EPUB 3 popup endnotes (`epub:type="noteref"`
  + a notes section) instead of the inline span.
* **`--paragraph-headings`** opt-in to surface
  paragraph titles as scene headers for authors
  who use them deliberately.

### R.2.b — Audiobook polish

* **Parallel synthesis** — synthesise chapters
  concurrently (CPU-bound), capped at core count,
  to cut the roughly-real-time wall-clock.
* **Cover art** — embed the cover image into the
  `.m4b` metadata.
* **Configurable bitrate** — `--bitrate` flag
  (default 64k).

### R.3.b — `paragraph-too-long` doctor class

The optional doctor scan class flagged in the
R.3 plan: a paragraph whose read time exceeds a
threshold (e.g. 5 min at `reading_wpm`).  Info
severity, no autofix — an author-judgment
finding like the 1.2.16 narrative-audit classes.

### I.1.6 — DuckDB write batching

Deferred from the I.1 perf pass per the data:
it's the save path, not profiled by the read-path
`_bench-load`.  Needs a `_bench-save` companion
instrument first, then coalesce per-save DuckDB
commits with a window.  Smaller win than the
I.1.4/I.1.5 algorithmic fixes; revisit if a
save-heavy workload shows up in profiling.

### I.1.2.b — In-process bench scenarios

The bench harness ships subprocess-style
`startup` + `search`.  Three scenarios from the
plan need in-process access (a subprocess
spawn's ~85 ms swamps a 0.05 ms flatten):

* `tree_scroll` — the now-O(n) flatten.
* `ai_envelope` — RAG retrieval + prompt build.
* `paragraph_save` — full save round-trip.

These land alongside a lib+bin crate split (a
larger refactor) or a hidden `_bench <op>`
subcommand per scenario.

### I.1.1.b — Fixture system-book population

`gen-fixture` ships the user-book backbone.
Deferred: Characters / Places / Threads
population, inline comments, tags — improves
bench realism without blocking the harness.  Also
an optional `--no-embed` flag so startup / tree
scenarios can skip the slow embedding step.

## Carryovers from 1.2.17

### T.4.b — Voice integrity verification (MD5)

The catalog exposes `md5_digest`; T.4 ships voice
auto-download without verifying it.  Add a
subprocess `md5sum` / `md5 -q` / `certutil` check
after download.

### T.6.b — Background voice downloads

The `Ctrl+B Shift+V` picker blocks the UI during
a voice download.  Lift to a tokio task + a
status-bar progress chip (the 1.2.15 health-
monitor pattern).  Note: the R.2 audiobook export
uses blocking synth by design (batch job), so
this is a TUI-picker concern only.

### Apple Silicon Piper

Upstream packaging bug — `piper_macos_aarch64.tar.gz`
ships x86_64.  Track piper's GitHub for a real
arm64 build; flip the macOS `auto` default when
it lands.

## Themes under consideration

### AI maturity

* **Multi-paragraph envelope** — give the AI ±1
  paragraph so it stops producing abrupt openings
  / non-sequitur endings.
* **Character voice consistency** — pick a
  character + a chapter, ask "does X speak in
  their voice here?" against the Characters book.
* **Hot-reload `prompts.hjson`** — watch the
  mtime, reload on change.
* **AI streaming into the editor** — stream at
  the cursor (vs the AI pane), Esc cancels +
  undoes.

### Genre packs

Mystery + historical-fiction project templates
with style-rule packs (clue tracker, fair-play
audit, anachronism overlay co-shipping with
A.5.b).

### Reader experience (continued)

* **Reading-time doctor** — flag chapters whose
  read time is a wild outlier (pairs with R.3.b).
* **Per-character audiobook voices** — map a
  Piper voice per Characters entry so dialogue
  routes to that voice.

### Other candidates

* **Sixth supported language** — Italian /
  Portuguese / Japanese.
* **GitHub Release object backfill** for
  1.2.11–1.2.18.
