# Inkhaven 3.17.0 — Every Door Agrees · Pictures in the Build

_3.17.0 is a correctness release for the ConLang suite. Eleven defects found by
working a language end to end — from the phonology block through the dictionary
to translation and the printed book — are fixed under one track
(`LANG-BUGFIX-1`). The theme is agreement: the same headword check at every
door, the same key for one word, the same segment for one spelling, the same
sentence count in and out of the translator. No new store; one small
dependency (`unicode-normalization`); warning-free in everything touched._

_Two smaller tracks ship alongside: an imported book's shared image folder now
reaches the Typst build, and the Scrivener importer reads RTF through
`rtf-parser-tt 0.6`, which decodes Word, Cocoa and LibreOffice text the way
each of them writes it._

Full guides: [`CONLANG.md`](../CONLANG.md) ·

## The language no longer locks you out

**A bad phonology block is reported, not fatal.** One misspelled constraint
kind (`no_gemminate`) used to fail the whole `Phonology` parse with
`line 0 column 0`, and with it every inspector, the generator and the
translator. An unknown kind is now loaded as inert and reported; an undeclared
class in a template or constraint, a rule whose target is not a phoneme, a
romanization or tone rule that can never match — all are **findings with a
location** (`constraints[2]`, `templates.root[0] "C V N"`, `allophony[1]
"ai > e"`). The CLI prints each as a `phonology error:` / `phonology warning:`
line and continues; `language doctor` lists them under a new **Blocks** section
(and `blocks.findings` in `--json`), for Phonology, Grammar and Morphology
blocks alike. Malformed HJSON is still a hard error, now prefixed with the
paragraph title.

**One spelling, one segment.** Every string the phonology compares — inventory
graphemes and IPA, class members, rule atoms, lexicon headwords, your input — is
NFC-normalised, and the segmenter case-folds, so `Pata`, `pata` and a decomposed
`pãta` (`a` + U+0303) are the same phoneme sequence; `check`, `syllabify`,
`stress` and the dictionary bucket all agree. A segment that still fails to
match prints with its codepoint (`̃ (U+0303)`), never as a bare accent.

## One headword check at every door

`language add-word`, `add-word --import` (the CSV pre-flight), `language import`
(Toolbox / PolyGlot) and the in-TUI `+` chord now run **the same check**, so a
word one door accepts the others accept, and `export --format csv` →
`--import` round-trips:

- **Shape** — 1–64 characters, no control characters. Never skipped: the
  headword becomes a paragraph title and a file name. An empty word or a
  600-character one used to reach the filesystem.
- **Spelling, one authority** — when the language declares a Phonology
  inventory, every greedy-matched segment must be a declared phoneme, and the
  first unknown segment is named. Only without an inventory does
  `Meta/overview.alphabet` act as the whitelist, matched by *letter* (an entry
  such as `"Ch ch"` declares a digraph) with diacritics folded to the base
  letter — so the scaffold's A–Z alphabet accepts `éle` under `E` and rejects
  `ŋa`. `--force` skips the spelling check, and now works on a single
  `add-word`, not only on `--import`.

The CSV pre-flight's "phonology inventory" check had been a stub — it read a
`phonemes: [...]` list of strings that no shipped block has — and so never ran.
It runs now. Tutorial 50 describes the real check and the round trip.

**One word, one key.** `add-word` derived three keys from the raw headword and
they disagreed: the bucket took the first *character* (`ą́` and `atal` made two
subchapters, `a` and `a-2`), the duplicate check was ASCII-only (`ŋa` and `Ŋa`
were both accepted; `pata` noun blocked `pata` verb), and the title was the raw
string. Now the headword is keyed once — NFC for the title, case-folded for the
duplicate check, bucketed on the longest-matching alphabet letter or else the
first *base* letter — and a **homograph** (same spelling, different `type`) is
admitted as `pata (2)`; the same spelling with the same (or an empty) `type`
remains the duplicate the error names.

## The translator reads the whole paragraph

```
language translate Avesha "the stone. the river flows"
«stone». atal sora  (SVO · Tier 1 RBMT · confidence 0.20)
```

That used to print `atal sora` at confidence 0.90: the whole input was one
clause, the first sentence vanished, and the number said all was well. Input is
now split on `.`, `!`, `?` and line breaks (a `.` between two alphanumerics,
`3.5`, is not a terminator); each clause is analysed and rendered on its own and
the results re-joined with the source punctuation. A clause the analyser cannot
place is kept as `«…»`. The reported confidence is the **minimum** over the
clauses, so one untranslatable sentence is not averaged away. `reverse` and
`cross` get the same split; the `Ctrl+B Q` chord, which passes a whole
paragraph, now translates every sentence of it.

## Syllables: hiatus by default

`syllabify --word aia` returned `aia`, one syllable: every run of vowels was one
nucleus, and stress, scansion, the saturation metric and the generator's
template check inherited the error. Adjacent vowels are now **hiatus** — `aia`
is `a.i.a`, `paia` is `pa.ˈi.a` — unless the sequence is a declared diphthong:

```hjson
diphthongs: ["ai", "au"]    // vowel IPA sequences; one nucleus each
```

A diphthong declared as a phoneme of its own (`{ ipa: "ai", kind: "vowel" }`)
needs no entry. `Phonology::validate` warns on an entry that is not two or more
declared vowels.

## Pictures in the build

An imported book often keeps its figures in a shared folder,
`books/<slug>/images/`, referenced as `#image("…/images/media/x.png")` — and
they never compiled, because assembly wipes the artefacts folder each run and
Typst refuses to read outside it. `assemble_book` now copies that folder to
`<artefacts>/<slug>/images/`, so prose can use a root-absolute path at any
depth:

```typst
#image("/images/media/image1.png")
```

No-op when the folder is absent. Symlinks inside the folder are skipped, and a
symlinked `images/` folder itself is treated as absent, so a project cannot
point the copy at `~/.ssh` or `/`. The tree-copy primitive moved out of the
Piper voice installer into a small neutral `fsutil` module.

## Scrivener: RTF through `rtf-parser-tt` 0.6

The importer hands the raw bytes to the parser, which decodes `\'xx` through
the document code page or the font charset and honours `\ucN`, so the
importer's own pre-decode and ASCII-placeholder scheme is gone — on 0.6 it
corrupted LibreOffice's `\uN\'xx` form; on 0.5 it already lost the character.
`\par` becomes a Typst paragraph break, punctuation after a control word is
kept, hidden text and headers / footers are dropped, and footnotes are spliced
in at their reference as `#footnote[…]`. The direct `encoding_rs` dependency is
removed. Tests went from 12 to 27, covering Word and Cocoa unicode forms, raw
cp1251 bytes, font charsets and the malformed-input fallback.

## Fixed along the way

- **A `"` in a language title or font family broke the dictionary and grammar
  book**: three Typst string literals (the document title, both `text(font: …)`
  declarations) and the quadrat composer used the *markup* escaper inside
  `"…"`. A string-literal escaper now handles all four.
- **A `--phoneme /k/` with no `--name` wrote `/k/.svg`** — outside the glyph
  store — and a glyph name with a control character made the font builder
  panic. Glyph names are validated (no path separator, no leading `.`, at most
  64 characters, norad's rules) before any write, on `--slot`, on the font
  block at build time and in the UFO builder; `/k/` is read as the phoneme `k`.
- **The translation-memory sidecar was named from the raw language title.**
  It is now a slug (`old-avesha-sea.json`); a memory saved under the old
  lowercased name is still read and migrates on the next save.
- The `line 0 column 0` lockout message is gone: `serde_hjson` carries no
  position for a custom error, so validation findings carry their own
  location (`constraints[2]`, `templates.root[0] "C V N"`) instead.

## Upgrade notes

**Words that no longer pass.** `add-word` now applies the check that only
`--import` applied before, so a word your dictionary already holds may be
refused when you add its neighbour — most often a letter the Phonology block
does not declare. Add the phoneme (or, without an inventory, the alphabet
letter), or pass `--force` as on import. Existing entries are not touched; a
re-import of an exported dictionary that contains such words needs `--force`
once, after which it round-trips clean.

**Buckets and duplicates.** New entries bucket on the base letter (`é` under
`E`, `ą́` with `atal` under `A`); existing `É` or `a-2` subchapters are left as
they are, and every reader of the lexicon (the overlay, `translate`, `export`,
`doctor`) walks all buckets and sees their entries. One caveat: `remove-word`
and `show-word` look an entry up under the bucket the *new* rule derives, so a
word sitting in a pre-3.17 `É` bucket is not found by name — delete or move
that paragraph from the Tree, or re-import the dictionary with `--new`. A
case-variant duplicate (`Ŋa` beside `ŋa`) is refused from now on; an existing
pair stays until you remove one. Homographs are titled `word (2)`; the body's
`word` field is the plain spelling, so every reader of the lexicon sees both.

**Syllable counts change.** Any word with two adjacent vowels that is not a
declared diphthong gains syllables: stress moves, scansion re-counts, and
`generate-word`'s template check becomes stricter. Declare `diphthongs:` for
the sequences your language treats as one nucleus; nothing else needs to
change.

**Translation confidence is lower on mixed paragraphs**, because it is now the
minimum clause confidence rather than the mean. A script that thresholds
`lang.translate`'s `confidence` will see the drop on exactly the inputs that
used to over-report.

**Translation memory.** A language whose title is a single plain word keeps
its sidecar name (`avesha.json`); titles with spaces, slashes or diacritics
migrate to the slug on the next `remember` — nothing is lost either way.

**Books with a shared image folder** need no change: the copy is a no-op when
the folder is absent, and prose already using relative image paths keeps
working; `/images/...` is simply the path that now also works everywhere.
