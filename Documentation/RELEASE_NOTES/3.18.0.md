# Inkhaven 3.18.0 — Quieter, Faster, One Surface

_3.18.0 is a consolidation release for the ConLang suite. Ten items under one
track (`LANG-IMPROVE-1`) take the cost out of every language command, give
the author two results the engine used to withhold, and make the hundred-odd
`inkhaven language` subcommands read as one surface — the same output flag,
the same `--json`, the same sentences, a documented index that cannot drift.
No new store, no new dependency; one new bench (`benches/conlang.rs`);
warning-free in everything touched. Suite 3236._

Full guides: [`CONLANG.md`](../CONLANG.md) (with the new **Command index**) ·
[`CLI.md`](../CLI.md) (the `-o` and `--json` conventions) · the plan:
[`LANG-IMPROVE-1_PLAN.md`](../PROPOSALS/LANG-IMPROVE-1_PLAN.md) · the book
*Developing a Constructed Language*, re-stamped for 3.18.

## Quieter: the cost paid on every command

**One policy line, not ninety-one.** A project with scripting disabled used to
print a `WARN` per denied Bund word on its first store write. The per-word
lines are DEBUG now and one INFO summary names the count, the categories and
the three knobs that change it (`scripting.enabled_categories`,
`enabled_words`, `no_default_deny`). The Bund VM is built only when a project
has scripts — a bootstrap setting, or at least one `Script` node, counted
inside DuckDB without a hierarchy load — so a script-less project never pays
for it.

**One language model per command.** Every `language` command rebuilt the
language from the store, paragraph by paragraph, on each call. `LanguageModel`
now fetches a book's paragraphs in one batched read and applies the former
loaders' rules once (phonology, validator findings, morphology, typology,
varieties, contact, loan phonology, diachronics, dictionary, texts,
hypotheses, `Meta/overview`); a process-wide cache keyed by the subtree's node
count and latest `modified_at` hands the same `Arc` back until something
changes. Measured: a Bund script calling `ink.lang.translate` thirty times
went from 1110 ms to 425 ms; one-shot CLI commands are unchanged within noise.

**Import is a batch.** `add-word --import`, the Toolbox and PolyGlot
importers, `generate-lexicon`, `derive`, `derive-lexicon`, the TUI accept-words
chord and Bund `ink.lang.derive_add` all write through one `DictionaryWriter`:
one hierarchy load per batch instead of three per row, each entry written with
its final body (one atomic file write, one embedding batch), and the vector
index flushed once at `finish`. A 256-row CSV import went from 38.8 s to
16.9 s with a byte-identical export. Bund `ink.lang.add_word` now runs the
same spelling check as every other door.

## Results the author expected

**Multi-segment rules fire.** `ai > e / _ #` never matched, because a rule
target was one phoneme. Targets and replacements are now sequences —
`a i > e / _ #`, `t > t s / _ i`, insertion and deletion included — in the one
rewriter that serves allophony, tone sandhi, diachronics, ablaut and variety
sound changes. A joined token (`ai`) is split against the inventory when the
split is unambiguous; when it is not, `language doctor` warns with both
readings and asks for the spaces. Rule sets declared outside the phonology
block (diachronics, ablaut morphemes, variety sound changes) are resolved the
same way.

**The alphabet orders the dictionary.** The `alphabet` in `Meta/overview`
named the Dictionary's letter buckets but ordered nothing. It now gives every
headword a collation key: buckets sort by alphabet position, entries inside a
bucket letter by letter (homographs `word (2)` after the base; undeclared
letters follow by code point), and the dictionary book and every export use
the same order. `add-word` and every import land sorted; the new
`language sort-dictionary <lang> [--dry-run]` puts an older dictionary in
order, renaming the `NN-` prefixes in one pass per parent.

## One surface

**`-o, --output <PATH>` everywhere.** The twelve `language` commands that
write a user-named file (`export`, `sketch`, `scaffold`, `dictionary`,
`grammar-book`, `tutorial`, `ecology`, `font-build`, `font-compose`,
`spatial-typst`, `glyph-draft`, `export-translation`) take `-o`; `--out` (and
`--svg` on `ecology`) stay as hidden aliases, so scripts keep working.
`font-build` without `-o` writes under the project's `exports/<lang>/fonts/`
folder and prints the path. A unit test pins the inventory.

**Counts are validated by clap.** `--count 0` on `compose`, `generate-word`,
`dialects`, `propose-loans` and `generate-lexicon` used to run and blame the
constraints; the flags are unsigned with a minimum of 1, `generate-word`
bounded at 100 000, and a batch in which no candidate passes is an error that
names the count and points at `language doctor`.

**One wording.** A new `wording` module owns the sentences the family repeats:
every "not found" says `run inkhaven language init <name> first`, hints quote
`inkhaven language font-build …` in full, counts read `1 entry` / `12 entries`,
the `compose --kind` error lists its kinds (now including `ceremony` and the
aliases) from the same table the match uses, stress rules print as words in
the LLM prompts, "wrote … → path" confirmations go to stderr and stdout
carries data only.

**`--json` where a script needs it.** `generate-word`, `syllabify`, `ipa`,
`stress`, `romanize`, `tone`, `scan`, `list`, `paradigm`, `sentence`, `gloss`,
`memory`, `varieties`, `dialects`, `cognates`, `family-tree` and
`sound-change` gain `--json`. Where the matching Bund word already returns a
structure the CLI emits the same keys; where it returns one string the CLI
emits an object with the fields its text output shows; each shape derives
`Deserialize` and a round-trip test pins its keys. Bund:
`ink.lang.export_translation` is the canonical name of the `.itm` exporter
(`ink.lang.export` kept as an alias), `ink.lang.generate_words ( lang role
count -- list )` returns the batch the CLI prints, and `ink.lang.list` returns
`[{name, entries, grammar, phonology, samples}]`.

**Docs that cannot drift.** `CONLANG.md` gains a generated **Command index** —
every visible `language` subcommand under twelve headings, one line each from
its own help, with `--json` / `-o` marks — produced by the hidden maintainer
command `inkhaven language _index-markdown`. A drift test checks every
`inkhaven language <name>` and `--flag` written in `CONLANG.md`, `CLI.md` and
the tutorials against clap, so the next stale doc fails the build. Tutorial 49
no longer promises a `language test` command and lists the nine real export
formats.

## Fixed along the way

- `translate --help` showed the `lect` description; the doc comment is back on
  its own variant.
- Dictionary entries stored as HJSON are `.typ` files on disk with only the
  content type flipped; the store's reorder primitives (`shift_sibling_order`,
  `swap_siblings`, the new `reorder_children`) now rename by the file field
  the node actually carries, so `swap_siblings` on a dictionary entry no longer
  fails with *not found*.
- The top-level `ai` command declares `-p` twice (`provider`, `project`); the
  whole-tree clap assertion would fail on it, so the new tests assert the
  `language` subtree. Noted in the plan; untouched here.

## Upgrade notes

**Rules you wrote with a joined target now fire.** An allophony, sandhi,
diachronic or variety rule such as `ai > e / _ #` that silently never matched
before 3.18 applies now. Re-run `language ipa`, `derive-lexicon` or
`dialects` on a language that carries such rules and review the surface forms;
`language doctor` flags any token whose split is ambiguous.

**Dictionary order.** New entries land in alphabet order; a dictionary built
before 3.18 keeps its old order until you run
`inkhaven language sort-dictionary <lang>` (preview with `--dry-run`). Exports
and the dictionary book are sorted by the alphabet regardless.

**`ink.lang.list` returns dictionaries, not names.** A script that looped over
the old list of strings should read `name` from each row. `ink.lang.export`
still works; new scripts should say `ink.lang.export_translation`.

**stdout is data.** Confirmations such as `Avesha grammar (typ) → grammar.typ`
moved to stderr; a script that captured stdout for the path should read stderr
(or use `--json` where the command offers it). `--count 0` is refused by clap
with exit code 2 instead of running.

**`font-build` default location.** Without `-o` the font is written under
`<project>/exports/<lang>/fonts/` rather than the current directory; the
command prints the path. `--out` and `ecology --svg` are accepted as hidden
aliases of `-o`.
