# Inkhaven 1.6.17 — The Dialectician & Any Provider

_A Socratic reader for your research corpus, and an LLM client that runs against
whatever key you actually have. No new runtime crates._

## `/socrates` — Inner Socrates over the corpus

Inner Socrates reads your manuscript prose and asks the questions it must answer.
`/socrates [topic]` (in the Research Assistant, plus `inkhaven research --socrates
<topic>`) turns that same Dialectician on the **collected Facts** instead: given a
topic — or the whole corpus — it asks the Socratic questions your gathered material
must answer to stand: what the facts treat as given, what would refute them, the
objection left unaddressed.

It's the **questioning** complement to SCHOLAR's *detecting* (`/contradict`,
`/relate`): where those find clashes and confirmations, this presses the corpus on
its own assumptions. It reuses Inner Socrates' Dialectician persona and slow-track
prompt verbatim; only the target (a facts block, retrieved for the topic) and the
framing (academic/philosophy, not fiction) differ.

## Any provider — LLM fallback

The LLM client used to hard-fail when the configured `default` provider's API key
wasn't set (`GEMINI_API_KEY not set …`), even if you had a *different* provider's key
in your environment. Now it **falls back to any configured provider whose key is
actually available** — or a keyless local provider like Ollama — so a project set up
for one provider still runs against the model you've got.

It's controllable: `llm.auto_fallback` (default `true`) — set it to `false` to keep
the strict behavior (fail with a clear error rather than switch providers) for users
who want the configured provider or nothing. Affects every AI feature.

## Dependencies & compatibility

**No new runtime crates.** New command `/socrates` (+ `--socrates` CLI twin); new
config `llm.auto_fallback` (defaults to the new behavior; existing configs pick it up
automatically). Everything is additive — existing projects are unaffected. Test suite
→ 2417.
