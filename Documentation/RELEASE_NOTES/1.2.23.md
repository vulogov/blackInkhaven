## Known bugs to fix

### Broken-pipe writes a crash report

Piping inkhaven's stdout into a truncating consumer (`… | head`) makes a
`println!` fail with `Broken pipe (os error 32)`, the panic hook fires, and
a `inkhaven-crash-<UTC>.hjson` is written to cwd (seen twice during this
cycle's smoke tests).  A SIGPIPE / broken-pipe on stdout is normal shell
behaviour, not a crash — it should exit quietly, not emit a crash report.
Fix: install the default SIGPIPE handler (or treat broken-pipe stdout
errors as a clean exit) so CLI output piping is well-behaved.
