# Inkhaven 3.7.0 — The TUI Pass: Keys, Editing, Consistency

_A release dedicated to the terminal experience itself — no new reader or axis.
It makes chords work across terminals, fixes the editing papercuts you hit every
keystroke, and finishes the dashboard-consistency story. Everything came from a
five-agent audit of the TUI + editor._

Three tracks. Deterministic, no new runtime crates, warning-free; the suite grew
to **3009**.

## Track K · Keys that actually arrive

- **Real keyboard-protocol detection.** Inkhaven requested the kitty keyboard
  protocol but never checked whether the terminal *answered*. It now queries
  `supports_keyboard_enhancement()` and, when the terminal doesn't support it
  (e.g. macOS **Terminal.app**), prints a one-time startup notice naming the
  terminal and the affected chords — `Ctrl+I`≡`Tab`, `Ctrl+M`≡`Enter`, some
  F-keys — with the fix (kitty / WezTerm / Ghostty / iTerm2 ≥ 3.5, and macOS's
  “use F1/F2 as standard function keys”). `$TERM_PROGRAM` now rides along in the
  crash report. There's a new **Terminal compatibility** section in
  `KEYBINDING.md`.
- **Block selection that works everywhere — `Ctrl+Z v`.** The old vertical
  block-selection needed `Alt`+arrows, which failed two ways: many terminals
  never deliver `Alt`+arrow, and `Alt+Left`/`Alt+Right` were *also* claimed by
  browser back/forward — so it was broken even in kitty. The new mode anchors the
  rectangle and lets **plain arrows** extend it (no modifier → no delivery or
  aliasing problem); `c`/`Enter` copy + exit, `Esc` cancels.
- **Secondary-TUI parity.** The prompts and config editors captured the mouse but
  never used it (killing native drag-select); that's dropped. A panic in the
  worldbuilder no longer leaks mouse capture. And all three secondary editors now
  request the keyboard protocol so their chords disambiguate like the main
  editor's.

## Track A · Input & editing correctness

- **Bracketed paste.** A terminal paste (Cmd/Ctrl+V, middle-click) used to stream
  as individual keys — so auto-pair mangled pasted Typst, snippet expansion fired
  per character, and a multi-line paste into the AI prompt or search **submitted
  at the first newline**. Paste now arrives as one event and is inserted in bulk
  at the focused target.
- **Quotes stop fighting prose.** With auto-pairing on, `don't` became `don''t`
  and every quote next to a word spawned a phantom closer. Quotes now auto-pair
  only when they read as an *opening* quote (not adjacent to a word char);
  brackets still always pair.
- **Search from the cursor.** Find used to jump to the document-*top* match; it
  now starts from the first match **at/after the cursor**. Added a backward step
  (`Ctrl+G` previous, pairing with `Ctrl+X` next).
- **Editor niceties** on the `Ctrl+Z` layer: **`Ctrl+Z g`** go-to-line (jump
  centred), **`Ctrl+Z w`** toggle soft-wrap live, **`Ctrl+Z t`** strip trailing
  whitespace (one undoable edit), **`Ctrl+Z m`** jump to the matching bracket
  (across lines, respecting nesting), and **smart Home** (plain `Home` → first
  non-blank column, then column 0).

## Track C · Consistency & discoverability

- **The dashboard navigation reaches every dashboard.** 3.6.0 gave the seven
  reader dashboards a shared `PgUp/PgDn/Home/End` + blank-row-skip navigation;
  eight more (Story Bible, ConLang hub, Character arc, Graph neighbourhood, World
  overview, Dialogue fingerprint, Style report, Inner-Socrates overview) were
  still `↑↓`-only. All 15 now share it.
- **Honest footers + scroll position.** Every dashboard footer advertised only
  `↑↓`, so the richer navigation was undiscoverable, and long ledgers gave no
  sense of position. A shared footer helper now renders
  `↑↓/PgUp/PgDn/Home/End · <keys> · Esc  (a–b of N)` on all 15.
- **Quick-reference drift fixed.** The `Ctrl+B H` quick reference hand-typed an
  incomplete, drifting set of F-keys in its Global section (`F1/F7/F9/F10`
  duplicated the live keymap section while **F8 was missing**). Those rows now
  come from the live keymap, guarded by a test so the drift can't return.

## Deferred as follow-ups

The always-on **matching-bracket highlight** (the jump ships; the highlight needs
both editor span-builders touched in the render hot-loop — a rendering-track
change). The rendering-track items generally (event-driven redraw, wide-char
columns) and the layout track (resizable panes, split-view sync-scroll) were not
in this release's scope.

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and
**macOS** (`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX
bindings ship no windows-gnu prebuilt).
