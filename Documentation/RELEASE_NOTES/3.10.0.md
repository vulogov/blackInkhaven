# Inkhaven 3.10.0 — Own the Index

_Two tracks aimed at one key. **F1 help now builds itself** — one command fetches,
curates, and indexes inkhaven's own documentation, so you never hand-assemble a
help corpus again. And **inkhaven now owns its vector index**: the abandoned
`vecstore` crate is gone, replaced by an in-tree store built directly on
`hnsw_rs` that *loads* the search graph on open instead of rebuilding it from
scratch. Together they take the first F1 search from **40–60 seconds to about a
second**. No new reader or axis._

Deterministic core, warning-free; the suite holds at **3036**. One new direct
dependency (`hnsw_rs`), and a net *removal* of transitive crates (vecstore's
tree, including `tracing-serde` and `ordered-float`).

---

# Own the index

The single biggest change is invisible until you notice how much faster search
is. The story is why it was slow, and what replaced it.

## The old store rebuilt the graph on every open

Inkhaven's semantic search — F1 help, Book chat, every reader that retrieves
paragraphs — runs on an HNSW nearest-neighbour index. That index lived in
`vecstore`, a third-party crate that had been **abandoned**. Its fatal habit:
on every open it **rebuilt the entire graph from raw vectors**, because its
generic distance-metric design made the persisted graph awkward to reload. For
inkhaven's corpus that was **15–31 seconds of reconstruction**, and it landed on
the *first search of the session* — which is exactly the moment you hit F1 with a
question.

## The owned store loads the graph instead

`vecstore` is now replaced by an in-tree store (`src/storage/hnsw_store.rs`)
built directly on `hnsw_rs`. Inkhaven only ever uses **cosine** distance, so the
polymorphism that stopped vecstore from reloading never arises — the owned store
**loads the persisted graph directly** (~50 ms for ~10k points) and skips the
rebuild entirely. Writes stay incremental: saving a paragraph inserts just that
paragraph's vector into the live graph and re-dumps. A record map is the durable
source of truth; the graph is a rebuildable accelerator over it, with over-search
that tolerates deleted points and automatic compaction so a long editing session
can't bloat the index.

## And the database wasn't checkpointing

With the graph load fixed, one cost remained: opening the DuckDB stores took
**~10 seconds**. `rebuild-help` and `reindex` wrote thousands of rows but never
checkpointed, so the data sat in the write-ahead log and was **replayed on every
open**. Both commands now checkpoint after a bulk write — draining the WAL into
the main database — so opens drop to **~90 ms** and stay fast.

**End to end:** a full F1 search went from ~18.7 s to ~1.7 s in a debug build;
release builds are quicker still.

## Upgrading is guided

The owned store can't read the old on-disk format, so a project built by an
earlier inkhaven opens with an **empty** index. That's detected: instead of a
bare "no results," F1 and `inkhaven search` tell you to run
**`inkhaven reindex`** (your books) and **`inkhaven rebuild-help`** (the F1
corpus). And `reindex` now recognises an empty index and **re-embeds every
document**, rather than skipping unchanged files — so the one command actually
rebuilds. Your prose is never at risk: the content is durable in the database;
only the derived index is rebuilt.

# F1 help that builds itself

Before this release, the F1 help corpus was something you assembled by hand. Now
one command owns it end to end.

## `inkhaven rebuild-help`

`rebuild-help` **fetches inkhaven's documentation from its GitHub repository**,
imports it into the Help system book, and indexes it — no local checkout, no
manual import. It's **curated**: release notes and internal planning docs are
filtered out (they're noise for a help question), leaving the manual, tutorials,
and reference. Large documents are **chunked by section**, each chunk carrying a
distinct section title, so a question like "how do I quit" retrieves the *Quit*
section rather than a whole chapter. Progress is shown per file, and the final
step persists and checkpoints a complete, ready index. `package-help-corpus`
builds the packaged `help-corpus.json` that the command consumes — now part of
the release cut.

**A note on network use:** inkhaven still doesn't phone home during ordinary
editing. `rebuild-help` is the one deliberate exception — it pulls the help
corpus from GitHub — and it's disclosed in the docs and the security notice.

## F1 that shows it's working

Submitting a help question used to **freeze the modal** while it searched. Now
the search runs on a **background thread** with an **animated spinner** in the AI
pane, so the UI stays live; F1 opens the AI pane with the grounded answer when
it's ready. When the Help book is empty, F1 points you straight at
`rebuild-help` instead of returning nothing.

# Configuration coverage

Two gaps in the reflective config editor, closed:

- **`Option`-`None` fields are now editable** — a setting that was unset could
  not be given a value from the TUI; it now recovers the right input type and
  accepts one.
- **The soft-wrap toggle persists** — flipping wrap in the editor now writes
  through to `inkhaven.hjson` instead of resetting next session.

---

## Upgrade checklist

After upgrading, run once per project:

```
inkhaven reindex        # rebuilds your books' search index
inkhaven rebuild-help   # rebuilds the F1 help corpus
```

Old `vectors/` files from the previous format are harmless and are overwritten on
the next save. No configuration changes are required.
