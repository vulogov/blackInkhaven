# Inkhaven 1.3.0 — From Draft to Submission + The Planning Board (planning)

_The first minor-version milestone since the 1.2 line.  1.2.x built the
deep **middle** of the writing lifecycle — drafting and revising.  1.3
fills the two **bookends**: getting a finished manuscript out the door
(print + submission), and planning a book before the prose exists.  Two
pillars._

## Pillar A — From Draft to Submission

Inkhaven can revise a book deeply but stops short of *finishing* one. This
pillar closes that gap, in three independent tracks:

- **Print production — [RFC PDF-1](../PROPOSALS/PDF-1.md)** (see the
  [implementation plan](../PROPOSALS/PDF-1_PLAN.md)).  A self-contained
  PDF subsystem: signature **imposition** for hand-binding / small print
  shops (the marquee feature), creep compensation, printer marks, page
  operations, cover-and-spine generation with ISBN barcode, preflight, and
  outline injection — pure-Rust (`lopdf`), single-binary, across CLI / TUI
  book-take / `ink.pdf.*` Bund stdlib.  Phased P0→P3 across 1.3.x.
- **Standard manuscript format** — a new export target for the
  shopping-a-manuscript path: double-spaced, 12 pt, running headers
  (author / title / page), `#` scene breaks, rounded word count.  Separate
  from PDF-1 (a render target, not a PDF-object op).
- **Submission package** — RAG-grounded query-letter / synopsis /
  comp-title helpers (a strong whole-book AI use) + a lightweight
  submission tracker.

## Pillar B — The Planning Board

The front of the lifecycle.  Inkhaven has the world (Facts) and chronology
(timeline) but no **plot-structure** layer.  The Planning Board adds one,
and — per the project lead — wires it into the existing knowledge books:

- Outline / beats / acts / turning points and **scene cards** (goal /
  conflict / disaster), in a corkboard/outline view tied to the
  Book→Chapter hierarchy + timeline + threads.
- **Integrates the Research book** — pull research notes into the planning
  surface so structure is built against what you've gathered.
- **Helps fill the Facts book** — planning surfaces the world-invariants a
  structure implies, feeding them into Facts (closing the loop with the
  1.2.21 Facts subsystem instead of starting it cold).

## Sequencing

Large cycle — two pillars + a multi-phase PDF subsystem.  PDF-1 leads
because it has a complete RFC + implementation plan; the manuscript-format
export and the Planning Board can scope in parallel.  Likely spread across
1.3.x point cuts (P0 imposition foundations first).

## Explicitly deferred

- **The Editorial Pass** (unify the detectors into one worklist) — a
  convenience/aggregation layer over tools that already exist and are
  individually runnable, not new capability.  For a power author it's a
  nice-to-have, not a need; revisit later as a thin pre-submission sweep,
  not a 1.3 headline.
- **The Whole-Book AI Editor** (RAG over the whole manuscript) → **1.4 or
  later**.  The most ambitious AI play; pairs naturally with the
  submission-package helpers when it lands.
