# Inkhaven 1.3.0 — The Editorial Pass (planning)

_The first minor-version milestone since the 1.2 line.  1.2.x built a
deep single-author tool with a dozen point analyses scattered across
chords and CLI commands; an author doesn't know which to run when.  1.3
unifies them: **one prioritized, navigable revision worklist** — "tell me
what to fix, and in what order."  It capitalises on the whole 1.2.x
investment and opens the runway to agentic editing (2.0)._

## The idea

Across 1.2.x we shipped many detectors, each its own surface:

- deterministic `doctor --scan` classes — `echo-repetition`,
  `continuity-drift`, `unresolved-tension`, `dropped-character`,
  `pacing-collapse`, `stalled-thread`, `naming-inconsistency`,
  `paragraph-too-long`, …
- AI-backed sidecar passes — `continuity` bible, `tension` ledger,
  `facts scan` contradictions, show-don't-tell, sentence-rhythm.

The 1.2.16 dashboard aggregates *metrics*; nothing aggregates *findings*.
1.3 = **The Editorial Pass**: one command that runs every analysis into a
single severity-ranked, jump-to-location, dismissable, re-runnable
worklist — with `--json` for a CI gate.  The sum becomes greater than the
parts, and an author finally has one answer to "what should I fix?".

Why it's the right 1.3: it builds *on* everything 1.2.x shipped rather
than adding a thirteenth sibling, and it's the clean opener for an
agentic-editing 2.0 — where the AI drives a review→propose→apply loop on
top of the **review-gated apply substrate** shipped in 1.2.22
(`replace::apply_project` + the review modal).

## Proposed shape (to refine)

- **E.1 — a unified `Finding` model + aggregator.**  One
  `Finding { class, severity, location, message, source }`.  The
  deterministic doctor scans and the AI sidecars both normalise into it;
  the aggregator runs the set, dedupes, and severity-ranks.  The shared
  `Hierarchy::user_book_chapters()` walk (1.2.23 D.8) is the iteration
  seam.
- **E.2 — the worklist (TUI).**  A navigable panel over the ranked
  findings: jump to location, dismiss, filter by class/severity,
  re-run.  Built on the modal patterns from the Facts/replace work.
- **E.3 — the report (CLI).**  `inkhaven review` (name TBD) → the same
  aggregation, human-readable + `--json` for CI.
- **E.4 — apply bridge.**  Where a finding has a mechanical fix, offer it
  through the review-gated apply path — the first step toward agentic
  editing.
