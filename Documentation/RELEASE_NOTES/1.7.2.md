# Inkhaven 1.7.2 — The Consequence Tracer

_The linguistic layer gains its first interactive-development tool — a rehearsal
for a sound change before you commit it — and the first of the typed grammar
blocks the deeper syntax work will read. The conlang companion book is brought up
to date with the whole analysis layer. No new runtime crates._

## Preview a sound change before you make it

The most consequential thing you can do to a language is change its sounds: one
rule ripples through every word at once, and some of those ripples you will not
have foreseen. The new **Consequence Tracer** lets you look before you leap.

```sh
inkhaven language trace Eldar --rule "s > ʃ / _ i"
```

It applies the rule to a copy of your whole lexicon, re-derives every word
exactly as a real sound change would — reusing the same rewriter your diachronics
already use — and reports two things: **which words the change touches** (old form
beside new), and, more valuably, whether it would create **new homophones** —
words that were distinct but which the rule collapses onto the same form. A merger
like that is sometimes what you want and sometimes a quiet disaster; either way
you would rather know now. Nothing is written; it is a rehearsal.

It is a keystroke away inside the Linguistic companion, too: type `/trace s > ʃ /
_ i` into the chat and the diff prints inline, no AI call.

## Typed grammar blocks

The grammar chapter's typology has been a flat map of feature → answer. 1.7.2
adds the first **typed blocks** alongside it — the structured schema the later
syntax work will read:

- **`ug_parameters`** — principles-and-parameters settings (`head_final`,
  `pro_drop`, `wh_movement`, …).
- **`verb_classes`** — your verbs grouped by valence (intransitive, transitive,
  ditransitive, impersonal).

Both are optional; an existing grammar block is unchanged. A new command validates
them and — the useful part — checks that the generative parameters do not
*contradict* the WALS feature answers:

```sh
inkhaven language grammar-check Eldar
```

A `head_final: true` language whose `word_order` is SVO, or whose adpositions are
prepositions, is telling two different stories; the check flags the inconsistency.
A finding is a flag, not a hard error.

## The book, brought current

_Developing a Constructed Language_ — the companion book — gains a new part,
**Analysing Your Language**: a chapter on the Linguistic companion and the Inner
Linguist, and a chapter walking through the analysis verbs (`metrics`,
`naturalness`, `pairs`, `universals`) and the Consequence Tracer. The typology
chapter now covers all twenty-two features, and the command reference lists the
new commands.

## Dependencies & compatibility

**No new runtime crates.** Everything is additive — two new `language`
subcommands (`trace`, `grammar-check`), two optional grammar blocks; existing
projects, languages and grammar blocks are unchanged. Warning-free (binary and
tests). Test suite → 2503.
