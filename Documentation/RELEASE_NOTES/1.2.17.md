# Inkhaven 1.2.17 — TTS Piper transition

**Active scope locked 2026-06-01.**  This cycle
ships a single feature done properly: a full
TTS Piper transition with cross-platform parity,
auto-downloaded voices stored per project, and a
voice picker modal.

See `Documentation/PROPOSALS/1.2.17_PLAN.md` for
the eight-phase shape (T.1–T.8), test budget,
on-disk layout, locked design decisions, and
risk register.

The remainder of this file is the carryover
backlog — themes deferred to 1.2.17.b or 1.2.18
to keep TTS Piper as a single-feature release.

## Carryovers from 1.2.16

### I.1 — Performance pass

The 1.2.16 proposal scheduled `cargo flamegraph`
against a 10K-paragraph fixture + targeted fixes
(lazy tree row materialisation, background
embedding refresh, DuckDB write batching).
Pulled out late-cycle to keep 1.2.16 release-
ready on schedule; the work is more valuable
with its own design + benchmark-pinning
iteration here.

Concrete first steps:

* Fixture: build a synthetic 10K-paragraph
  project (script in `tools/`) with realistic
  prose distribution + thread + comment
  density.
* Baseline: capture startup time, first-render
  time, tree pane scroll cost, search round-
  trip, AI envelope assembly time.
* Profile: `cargo flamegraph` per scenario.
* Fix: one PR per hotspot, each tied to a
  benchmark threshold that fails CI on
  regression.

### A.2.b — Dashboard sections

Each adds one row to the existing `Ctrl+V
Shift+J` modal; no new infrastructure needed.

* **POV chip** — most-mentioned character in
  the active book (heuristic from
  `pov_tracker`).
* **Rhythm gauge** — sentence-rhythm CV across
  the project, paired with the per-paragraph
  `Ctrl+B Shift+H` modal.
* **Filter-words flagged today** — count of
  style-warning hits per the existing overlay
  toggled by `Ctrl+B Shift+F`.
* **Recent AI critique** — first ~120 chars of
  the most recent AI history entry, so the
  dashboard reminds the author of the last
  critique they got.

### A.6.b — Unresolved-tension detector

The fourth A.6 plot-mining class.  Deferred
because the heuristic needs real-manuscript
calibration before its false-positive rate is
predictable.

Candidate shape: detect an introduced conflict
/ goal / question that lacks a resolution
paragraph downstream.  Probably needs a small
LLM-assisted classifier ("does this paragraph
introduce or resolve a tension?") rather than
a pure regex / keyword approach.

### A.5.b — Worldbuilding pack additions

* **Numeric / spatial contradictions** —
  number-word extraction across prose +
  consistency check (`three days later` after
  `a week passed`; `200 leagues north` after
  `200 leagues south`).
* **Anachronism overlay** — flag period-
  inappropriate vocabulary against the
  project's declared setting (HJSON
  `project.setting_period`); render as a
  style-warning overlay toggled with the
  existing `Ctrl+B Shift+F` infrastructure.

Both need number-words extraction +
preposition parsing + editor render infra
that doesn't yet exist.

### I.4.b/c — Bund stdlib follow-ups

* `ink.thread.add_waypoint(thread_uuid,
  paragraph_uuid)` — append a waypoint to a
  thread programmatically.
* `ink.thread.link_paragraph(thread_uuid,
  paragraph_uuid)` — same but for the
  alternate paragraph-link relation.
* `ink.workflow.chain([prog_a, prog_b, ...])`
  — composability primitive so scripts can
  declare multi-step author workflows.

Each follows the I.4.a pattern (registered in
`src/scripting/stdlib/`, declared category in
`policy.rs`, contract tests for the policy
boundary).

## Carryovers from 1.2.15

### Phase G — Git / backup safety rails

The 1.2.15 proposal listed Phase G out of scope
"to keep 1.2.15 scope crisp"; 1.2.16 closed the
backup-freshness amber chip slice (P.1).  Still
outstanding:

* **Uncommitted-changes warning at TUI exit** —
  detect a dirty git working tree on exit;
  surface a status-line warning (and an opt-in
  confirm) so users don't leave their changes
  behind.
* **Disk-space pre-flight** — before save /
  assemble / backup operations, check free
  space and refuse to start under critical-low
  conditions instead of trapping a write error
  half-way through.

The disk-space check needs a `fs2` or `sysinfo`
dependency (no platform-portable disk-free in
std).  Worth the dep if the broader release
needs it; alone it isn't.

### M1 — Crash-report action-ring detail hygiene

Audit every `crash::context().push_action(...)`
call site and document the rule that `detail`
must carry structural metadata only (slug
names, counts, anchor IDs), never raw user
input.  Truncate `detail` to ~80 chars at
insertion as defence-in-depth.

Already documented in
`Documentation/SECURITY_WARNING.md` §3.5 +
§4.2; the code-side audit is the open work.

### M3 — Script-initiated `ink.input` modal prefix

Prefix modals opened by Bund scripts with a
visible `[script: <slug>]` tag so users can
distinguish them from inkhaven-internal
prompts.  Mitigation for the "phishing prompt"
class flagged in the 1.2.15 security audit.

## Themes under consideration

### TTS — Piper transition

The 1.2.9 `Ctrl+B S` TTS surface uses macOS
`say` / `AVSpeechSynthesizer`.  Plan: replace
with [Piper](https://github.com/rhasspy/piper)
so TTS works on Linux + Windows + macOS with
high-quality neural voices, no platform fork.

Sketch:

* Bundle `piper` binary + voice models in the
  release artefacts (`release.yml`).
* `tts.engine: "system" | "piper"` HJSON key
  (default `"system"` for compat in 1.2.17,
  flip to `"piper"` in 1.2.18 after a cycle of
  field testing).
* `tts.voice` field maps to a Piper voice name
  (`en_US-lessac-medium`, etc.).
* `inkhaven doctor --tts-test` extended to
  verify the Piper binary + voice model on
  disk.
