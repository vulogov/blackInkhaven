# Inkhaven 2.0.0 — The Semantic Net

_Inkhaven has always been a knowledge graph — it just didn't know it. Every book,
chapter, paragraph, fact, character, place, and source is one uniform node, stored in one
database, embedded for semantic search. What was missing was **edges**: a first-class,
persisted, typed way to say "this fact contradicts that source", "this paragraph links to
that one", "this word means this concept". 2.0 is the edges._

The flagship of 2.0 is **SEMNET** — a knowledge-graph layer that overlays the nodes you
already have and connects them into one interrogable whole. It doesn't replace the
manuscript tree or the vector index; it draws the lines between them. And you never lose
data to it: edges annotate your nodes, most of them are derived, and you can throw the
whole graph away and rebuild it from your manuscript, sidecars, and dictionaries.

See [`Documentation/GRAPH.md`](../GRAPH.md) for the full reference.

## What the graph knows

The graph starts empty and fills from everything the project already tracks — each source
becoming a typed edge:

- **Structure** — paragraph links (`links_to`) and timeline event involvements
  (`event_involves`), lifted from your node fields.
- **Provenance & verdicts** — where each fact came from (`sourced_from`) and its
  `/factcheck` grade (`graded_as`), so facts group by source or by verdict.
- **Stance** — the judged relations `Ctrl+V ?` confront and `/relate` produce, which used
  to be rendered and discarded, now **persist** as `contradicts` / `in_tension` /
  `qualifies` / `agrees` edges that accumulate. Promote the ones that stick; dismiss the rest.
- **Citations** — `@key[locus]` primary-source references (`cites_locus`, with scripture
  canonicalization so `John 3:16`, `Иоанна 3:16`, and `Joh 3.16` collapse to one locus) and
  the snowball citation neighbourhood (`cites`, work → work).
- **The lexicon** — the WordNet semantic net, finally connected to the manuscript: the
  words your prose uses link to their senses (`mentions`), the local taxonomy
  (`hypernym` / `hyponym` / `antonym`), and the cross-lingual interlingual pivot
  (`translates`).
- **The declared world** — each book's cast, symbols, motifs, and open tensions
  (`declares`).

## Populating & querying it

Three actions fill the graph, and one command reads it:

```
inkhaven graph rebuild      # derive the structural edges from your project
inkhaven graph lexical      # import the WordNet bridge for the project language
inkhaven graph stats        # counts + a per-kind breakdown
inkhaven graph neighbors <node>       # the node's one-hop neighbourhood, as a tree
inkhaven graph contradicting <node>   # the stance clashes touching a node
inkhaven graph loci <node>            # the primary-source loci a node cites
inkhaven graph paths <from> <to>      # a bounded citation / link path
inkhaven graph promote <edge> | dismiss <edge>
```

Confront (`Ctrl+V ?`) also persists its judgements live as you write.

## In the editor

- **`Ctrl+V g`** opens the neighbourhood view for the paragraph you're editing — a
  read-only tree of its one-hop edges (what it links to, contradicts, is sourced from,
  cites, and the senses it mentions), grouped by kind with direction arrows. `↑↓` scroll,
  `Esc` closes.
- On a **confront finding** in the Output pane, **`P`** promotes its stance edge to a kept
  decision (survives `graph rebuild`) and **`d`** rejects it (deletes the edge).

## The Inner family reads the graph

The shared grounding the Inner-family readers see now also reports what the *graph* has
established — recurring character pairings (who keeps appearing together across your scenes)
and the count of unresolved factual contradictions — relational context no single declared-
data store could compute.

## Multilingual, crash-safe, benched

The graph is multilingual by construction: edge kinds are language-neutral, loci collapse
across spellings, and the lexical bridge crosses languages through the interlingual index.
The edge store (`edges.db`) is a DuckDB store beside your metadata: writes are atomic, it
survives a `kill -9` mid-write, and deleting a node cascades its edges away. A `graph`
bench guards the edge-insert throughput and the reverse-index neighbour-query latency in
CI, alongside the render / scale / export gates.

## Also in 2.0

- The performance/stability harness (multilingual `gen-fixture`, the render / scale /
  export / index / graph benches, an on-demand 10k baseline).
- A two-round adversarial stability audit whose four findings were all fixed with
  regression tests.
- Event-driven redraw was evaluated and **deliberately postponed** — the idle repaint is
  negligible and the rewrite's complexity isn't worth it.

## Platform note

Supported release targets remain **Linux** (`x86_64-unknown-linux-gnu`) and **macOS**
(`aarch64-apple-darwin`). Windows stays deferred (the `ort-sys` ONNX bindings ship no
windows-gnu prebuilt); see `Documentation/2.0_READINESS.md`.
