# Inkhaven 3.20.0 — Every Surface Checked

_3.20.0 finishes the verification track 3.19.0 opened. The main editor was
probed key by key last release; this one does the same for the two
standalone editors (`inkhaven config`, `inkhaven prompts-editor`), closes
the one modal the main-editor probe could not reach, and then turns to the
command line: a walker over the whole clap tree and a docs-drift test that
reads every `inkhaven …` line in the documentation. Fifteen defects fixed
in the editors, one short-flag collision, twenty-four commands brought onto
`-o/--output`, nine stale invocations in the docs. No new dependency, no
new store; warning-free in everything touched. Suite 3266 (+17 ignored)._

Full guides: [`KEYBINDING.md`](../KEYBINDING.md) (new `inkhaven config`
section; the prompts-editor section rewritten) ·
[`CLI.md`](../CLI.md) (the whole-surface conventions).

## The config editor

**Every box takes the shared chord set.** The int, float, string, colour,
path and list-entry boxes, the map-entry name and the annotation editor
were bare strings: no cursor, no `←`/`→`, no `Home`/`End`, `Backspace`
only. They are one-line text inputs now (`KEYBINDING.md` §4.5): cursor
moves, word moves, `Ctrl+U`/`Ctrl+K` kills, a drawn cursor, a long value
windowing to its box. A box refuses what it cannot hold — a letter in an
int box, a non-hex digit in a colour — instead of swallowing the key.

**A chorded letter is never a bare key.** `Ctrl+D` staged a map-entry
deletion, `Alt+E` opened an editor, `Ctrl+R` inside a list box reset the
field. Only `Ctrl+H` (help) is a chord the tree owns.

**No dead ends, no overflow.** The help pane scrolls (`↑↓` / `PgUp` /
`PgDn`, clamped to the body; any other key closes). The rollback picker
windows around its cursor — a long backup list walked it off screen. Every
modal is fitted to the terminal rather than painted outside a small frame.
The tree cursor stays on a row when a collapse or a dropped entry shortens
the list. The detail pane no longer tells you to add entries "via the HJSON
editor for now" — `a` and `d` have done that since 1.2.10.

## The prompts editor

**`?` types.** It opened help from the editor pane and the AI prompt, so a
template could not hold a question mark. Help is `Ctrl+H` there; `?` still
opens it from the list.

**The AI response pane scrolls.** It never did: a long review was clipped
at the box. `Ctrl+B ↑`/`↓` scroll a line, `Ctrl+B PgUp`/`PgDn` a page,
`Ctrl+B Home`/`End` the ends, from any pane; `PgUp`/`PgDn` page it from the
prompt strip beneath. The offset clamps to the rendered extent, so the
opposite key always moves. A new send scrolls back to the top.

**The AI prompt is the shared box.** Word moves, kills, and the shared
history recall: `↓` past the newest entry brings back the draft you were
typing (it was wiped). A chorded `Enter` (`Ctrl+Enter`) no longer sends —
the rule the main editor's confirmations follow since 3.19. The add-prompt
name box is the same shared box.

**Chorded letters, lists, help, modals** — the same fixes as the config
editor: `Ctrl`/`Alt` letters never fire `a`/`d`/`l`, the rollback picker
windows, the help pane scrolls, modals are fitted. The "Phase 1 / Phase 2 /
Phase 3" copy from the 1.2.10 rollout is gone from the welcome banner, the
empty-list hint and the help body.

## The modal probe reaches everything

3.19's modal probe left one opener untested: the thesaurus needs an
installed WordNet. The probe now parses a five-word WN-LMF lexicon around
the word under the cursor into an in-memory index before opening, so the
real opener runs — two synonyms, a hypernym, an antonym — and the panel is
exercised the way a user reaches it. Unopened modals: 1 → 0.

## The command line

**A walker over the built clap tree** (`src/cli/surface.rs`) now runs in
the suite. Building the tree under clap's debug assertions caught a
collision that only a debug binary ever showed: `inkhaven ai --provider`
claimed `-p`, which is the global project flag on every command. It is
`--provider` only now.

**`-o/--output` everywhere.** `CLI.md` has said since 3.18 that a command
writing one file the user names takes `-o, --output <PATH>`, with the
`language` family converted and "tooling commands unchanged". The rest
follow now, each keeping `--out` as a hidden alias so scripts keep working:
`index`, `index-locorum`, `index-verborum`, `backup` (`-o/--output <DIR>`),
`package-help-corpus`, `research` (`--export-thread`, `--bibliography`),
`sources export`, `inner-socrates bundle export`, and every `pdf`
operation that writes a file; `pdf split` takes `--output-dir` (alias
`--out-dir`). `realworld gazetteer` and `tts test` already said `--output`
and gain the `-o` short. A unit test pins the convention, so the next
`--out` cannot land.

**The documentation is checked against the binary.** `docs_cli_surface`
reads every `inkhaven …` command line in the README, the guides, the Bund
reference and the tutorials (release notes and proposals are history and
are not checked) and resolves it against the command tree — the command
path, including aliases, and every `--flag`, including the globals. Nine
invocations had drifted: `export --format epub` (the format is
positional), `import-scrivener --source` (the path is positional),
`export-concordance --format json`, `export pdf --book` (`--book-name`),
`plan map … --chapter` (positional), `realworld fact-check` (it is
`inkhaven fact-check --timeline-aware on`), and a hypothetical
`export --as scrivener` quoted as a command. All fixed; `--out` reads
`--output` throughout.

An ignored inventory printer (`cli_surface_inventory`) lists the surface:
404 leaf commands, 115 of them with `--json`, 50 output-path arguments.

## The probes

Two new probes run in the default suite (no store, about 45 s together):
`config_tui_probe` (`src/config_tui/app/probe.rs`) and
`prompts_tui_probe` (`src/prompts_tui/app/probe.rs`), sharing
`src/probe_kit.rs` — the key battery, the nine sizes, a runner that keeps
the last panic message so an assertion inside a battery is still reported.
Each presses every battery key on the main view and inside every modal
(the config editor's thirteen modals and every widget kind, the prompts
editor's ten), renders at nine sizes from 8×3 to 200×60, checks that `Esc`
reaches the main view within three presses, then runs the scripted checks
above. Reports land in `<temp dir>/inkhaven-<name>-probe.txt`.

The five 3.19 probes are unchanged and still `#[ignore]`d (they open a
real store):

```text
cargo test --bin inkhaven -- --ignored --nocapture modal_probe
```

## Upgrade notes

**`inkhaven ai -p <provider>`** is `inkhaven ai --provider <provider>`;
`-p` is the project directory, as on every other command.

**`--out`** still works everywhere it did, as a hidden alias; `--help`
shows `-o, --output`. `pdf split --out-dir` is `--output-dir`.

**`?` in the prompts editor** types a question mark in the editor pane and
the AI prompt; press `Ctrl+H` for help there.

**`Ctrl+Enter` in the prompts editor's AI prompt** no longer sends; press
`Enter`.

**Existing projects open unchanged**; no on-disk shape moved.
